# 生物移动受阻等待

## 背景

生物无法到达目标时，每帧尝试不同避障方向会导致绳边、围栏、岸边等处反复挪动和转向。

## 需求描述

共用移动逻辑识别受阻，停止移动尝试一秒后重试，覆盖追击、逃跑、游荡、牵引和觅食移动。

## 设计方案

- `WildlifeMovement` 为每个动物保存临时移动记忆。前进及可用侧向全部失败时立即受阻，一秒内不调用路径探测，也不更新移动朝向或播放跑步动作。
- 连续移动约 0.5 秒后，若净位移小于 0.25 米且小于累计路程的 35%，视为原地往返，同样等待一秒。使用净位移而非到目标距离，不阻止绕障暂时远离目标，也不把正常慢走当成受阻。
- 绕行方向至少保持 0.6 秒；选定侧向无路时停下，等待结束后可重新选择另一侧。正常直行始终优先。
- 等待只限制自主移动，不清除仇恨、不阻止近身攻击或受击位移。熊等待时不发起扑击、不推进冲刺耗力和扬尘。死亡撤离使用原有独立路径流程。
- 状态按动物对象弱引用保存，不进入存档，不改变存档版本。非连续移动恢复时清理旧采样窗口。
- 房主运行判定，客人沿用既有位置、朝向快照插值，不自行探路或维护等待计时，不新增网络字段。

## 验证

`node scripts/test-wildlife-movement.mts` 检查一秒等待无探测、恢复移动、不同帧率的原地往返、正常慢走、稳定绕行侧向和个体隔离。运行时由用户验证绳边狼熊、围栏和岸边追击、逃跑及联机表现。
