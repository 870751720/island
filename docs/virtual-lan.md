# UU 虚拟局域网辅助直连

## 背景
浏览器可能未提供可用的虚拟网卡地址，或使用无法跨虚拟网络解析的 mDNS 名称。UU 组网成功不代表游戏握手必然成功。

## 需求描述
好友直连提供实验性本机虚拟 IPv4 输入和可复制的诊断。双方先加入同一 UU 房间，各填自己的地址，再使用六位游戏房间码联机；留空保持普通直连。不配置 TURN。

## 设计方案
- 创建大厅、加入大厅、游戏内开房弹窗共用触屏组件，输入和展开区域至少 44px。房间创建后地址锁定；游戏设置仍可查看诊断。地址仅本页临时使用，刷新清空，不写入存档或邀请链接。
- 每条 PeerNet 初始化时读取本页地址。保留浏览器原始候选，针对 UDP host 候选另发低优先级虚拟 IP 候选，保持端口及握手关联；去重且排除 TCP、srflx、relay。这不能保证该虚拟 IP 上的端口实际可达。
- 可选 virtualLan 标记区别辅助候选，与原候选共用信令及远端描述前队列。浏览器拒绝辅助候选时仅记录诊断，继续原有路径。房主和客人运行同一逻辑，双方应使用新版。
- 诊断按连接编号保留本页最近 40 条，包含地址收集、握手、ICE 状态、30 秒超时及双数据通道打开状态。连接建立时单次读取 getStats 选中候选对；信息缺失时如实显示。选中地址不能证明操作系统实际路由经过 UU。
- 诊断仅在本页内存供手动选择复制，不额外上传；候选仍通过现有信令交换。
- 中转模式、房主权威 Actions 结算、客人动作上行、快照回流、事件补播和自动重连保持原语义。协议版本和 SAVE_VERSION 不变。图鉴「与朋友联机」同步说明。

## 验证
自动检查覆盖地址校验、候选筛选与去重、原候选保留、先到候选排队、辅助拒绝隔离和普通直连回归。UU 实际可达性由用户双方设备验证：先开启 UU，再打开新版页面填地址开房/加入；失败时提供双方诊断和设备、浏览器信息。另对照留空地址的普通直连与服务器中转。
