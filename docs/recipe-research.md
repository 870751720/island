# 料理研究台与隐藏食谱

## 背景

面粉需要更多料理用途，通过食材搭配探索隐藏食谱，增加收集目标。所有交互优先适配手机触屏。

## 需求描述

- 三级工作台用木头 ×8、石头 ×5、绳子 ×2 制作料理研究台；可安放、用铲子整件回收。
- 自由投入 1～4 种食材，每种一份，无固定槽位或顺序。组合完全匹配必定成功；额外材料也算不匹配。
- 开始时扣材料，研究持续 2 秒。投入食材的图标跳动，显示进度条，播放现有烧烤音效。减少动态效果偏好下保留进度条，关闭跳动。
- 成功解锁食谱并获得对应食物 ×1；背包满时成品掉在脚边。失败消耗食材，结束后冷却 5 秒，冷却按玩家计时，换台或关闭面板不能绕过。
- 面板可关闭，研究继续；正在研究时锁定槽位，冷却时可准备下一组。存档保留剩余研究时间、冷却、投入食材与结果。
- 只显示未发现食谱的线索。失败两次后可查看进一步提示。已知组合禁止重复扣料；全部发现时引导查看食谱。
- 「已发现」页列出研究搭配、烹饪用量与持有数，新发现置顶。烹饪台「烹饪」区域仅列出已解锁隐藏料理，即使材料不足也可查看所需材料。

## 设计方案

### 当前已实现的料理

| 料理 | 研究搭配（各一份） | 每份烹饪用量 | 饥饿 / 口渴 / 生命恢复 |
| --- | --- | --- | --- |
| 草莓奶糕 | 面粉、草莓、羊奶 | 面粉 ×2、草莓 ×2、羊奶 ×1 | 42 / 12 / 15 |
| 苹果派 | 面粉、苹果 | 面粉 ×2、苹果 ×3 | 35 / 8 / 10 |
| 鲜肉馅饼 | 面粉、兽肉、胡萝卜、辣椒 | 面粉 ×2、兽肉 ×2、胡萝卜 ×1、辣椒 ×1 | 65 / 5 / 25 |

这三种料理不可喂动物。食材白名单包含生鲜食材与面粉，排除熟食、酒、饮料及非食材。

`HiddenRecipes` 集中配置研究组合、线索和烹饪用量；`ResearchTableSystem` 复用通用设施生命周期，按玩家独立结算。实体和食物均以 Three.js 基础几何体程序化建模，静态网格合并，不增加动态灯光。

个人永久收藏保存在 `island.recipe-discoveries.v1`，研究成功或实际获得成品均可解锁。跨本浏览器同源的存档、新游戏保留，不因死亡清档丢失；TapTap 手动备份包含该数据，旧备份缺省仍可读取。清除浏览器数据或切换站点来源不自动共享收藏。

图鉴未发现条目显示问号和「待发现」，隐藏名称、图片、属性和配方；搜索、直接打开和上一件/下一件都遵守该规则。发现后恢复完整条目。

烹饪复用原有五秒一份的燃料和队列系统，以隐藏料理 ID 表示多材料队列。取回或挖走设施时返还剩余份数对应的实际食材；成品独立收取。台上已有其他成品时需先收取，避免混合输出。

联机研究动作上行，房主校验范围、状态、组合及库存，再扣料计时。个人研究状态和发现列表随 HUD 快照回流，客人只表现进度与音效。加入时上传自己的永久收藏，其他玩家不自动共享；赠送成品由接收者实际入包后解锁。新设施走世界增量同步。研究进度支持会话存档恢复。网络协议版本更新为 49，存档版本保持 32。

### 新增 40 份隐藏料理设计（待实现）

以下为内容设计，尚未注册到游戏。保留原有三份，落地后总数为 43 份。全部使用现有研究食材，不新增种植、养殖或采集资源；不引入糖、盐、油、鸡蛋等尚未纳入研究白名单的材料。羊奶与牛奶严格区分，不互相替代。料理名称是荒岛简化做法，不额外要求现实烹饪辅料。

研究时将表内烹饪材料各投入一份，忽略表中的数量；正式烹饪才按完整数量扣除。每次产出一份，所有组合无序且唯一，不能多放材料。继续采用研究两秒、失败冷却五秒、烹饪五秒一份及现有燃料规则，不设随机成功率、研究前置链或额外设施等级。汤羹也沿用现有烹饪台规则，不额外扣水或容器。

恢复值依次为饥饿 / 口渴 / 生命，均为单份即时恢复的设计初值，实际受角色上限截断。所有新增料理不可喂动物，也不能作为下一道隐藏料理的研究原料。定位是食材用途、携带便利和收藏差异，不保证每道料理都比材料分别食用更划算。以下五组仅用于设计归类，不构成解锁门槛。

### 内容平衡与手机呈现（待实现）

- 面点偏饱食、低水分；汤羹偏补水；田园菜提供种植消耗出口；肉食偏饱食；海鲜偏综合恢复。最便宜的两材料配方不应同时在三项恢复上超过复杂配方。原有鲜肉馅饼 65 / 5 / 25、烤大鱼 40 / 20 / 20、黄金鱼料理 100 / 100 / 100 作为现有参照，新增普通料理不承担黄金鱼级全恢复功能。
- 初值需在实现时与材料生食、烧烤、煮食的总恢复量逐项对照，结合采集难度与每份格数确认取舍；重点关注能稳定量产的土豆、玉米与奶类，避免一种低成本料理包办全部需求。正式烹饪消耗多于首次研究是现有发现奖励，已知组合仍禁止反复研究获利。
- 研究面板保留「尝试料理」「已发现」两页，显示真实的已发现数 / 43。线索增加上一条、下一条及当前位置；只浏览未发现条目，不显示其名称或分类。首次提供可用食材较多的线索，其余仍可手动查看；这种排序不改变成功条件。
- 已发现列表增加名称搜索及「全部 / 材料充足」筛选，新发现置顶；烹饪台也提供材料充足筛选，默认仍能查阅全部已发现配方。筛选不改变收藏计数。375px 竖屏采用单列卡片，材料自动换行，按钮触控区至少 44px，滚动内容与底部操作区分离。
- 模型复用饼、糕、碗、炖锅、卷、串六种低面数程序化模板，以配色、切面与少量配料区分；只用 Three.js 基础几何体和现有黏土材质，合并静态网格，不加动态灯光。列表图标使用现有图标管线，避免同时创建 43 个实时 WebGL 预览。

### 图鉴、联机与存档接入（待实现）

新增物品的图鉴名称与上表一致，获取方式为「料理研究成功获得；发现后在烹饪台消耗所列食材制作；其他玩家赠送成品」。用途展示三项恢复值及不可喂动物；解锁条件仍为研究成功或实际获得成品，不增加等级门槛。未发现时名称、图标、属性和配方继续隐藏，搜索与详情跳转不得泄露。实现时同步注册物品、食物、模型、图标、来源关系及图鉴说明，并更新 `docs/wiki.md`、`docs/food-consumption.md`。

联机继续由客人发送 `researchStart` / `cookingBoil`，房主校验完整配方、发现状态、库存、距离及冷却，负责扣料、进度、产出与返料；客人仅显示确认后的状态与动画。个人发现列表和研究结果经 HUD 快照回流，断线期间的完成结果在重连快照中恢复，不靠动画事件发奖励。音效或提示按研究序号去重；世界设施继续走原有增量，共享成品仍由实际收取者解锁。

`ActionProtocol.ts` 当前将 `syncRecipeDiscoveries` 数量写死为 3；实现时必须改成由完整配方表推导的上限（本批为 43），校验 ID 白名单并去重合并。检查 HUD、会话存档、永久收藏、备份与面板中是否还有三份假设。新增 ID 后需要递增网络协议版本，避免不同配方表的房主与客人混连；协议版本按落地时仓库当前值递增。同步范围详见 [联机文档](./multiplayer.md#隐藏料理扩容设计待实现)。

保持现有三个料理 ID、永久收藏键和 `SAVE_VERSION` 不变。旧档原有发现保留，新增料理默认未发现；加载时继续按有效 ID 恢复，不因总量改变清空收藏。无需为本批内容编写存档迁移。

### 落地验收要求

1. 配方总数为 43；新增 ID 恰好 40 个且不冲突；每个研究组合有 1～4 种互不重复的白名单食材，与另外 42 个组合均不同；烹饪用量为正整数且材料集合与研究一致。
2. 原有三份仍正常匹配；新配方顺序任意均可发现，多放、少放或重复食材不能误匹配；已发现组合不能再扣研究材料。
3. 所有新增料理可以发现、烹饪、排队、收取、食用；取消或回收设施退回实际剩余食材；背包满时研究成品掉落；任何动物均不可食用。
4. 图鉴发现前后、提示与烹饪用量一致；手机竖屏中 43 份收藏可检索，长材料行不溢出，按钮可触达。
5. 房主与客人分别验证第 4、第 43 份发现、超过三份的收藏上传、赠送、满包、重连及研究中存档恢复；同一动作不能重复扣料或重复奖励。
6. 旧档和旧备份保留原有发现，新游戏沿用个人收藏；新增 ID 不触发旧档失效。实现后按仓库流程进行类型检查、H5 构建、ZIP 校验与固定入口解压、本地提交，再由用户做运行时验证。
