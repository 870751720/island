# 设备判定与手机横屏模式

## 背景

游戏以手机触屏为主要目标，需要统一设备判定，并在本机记住玩家的显示方向偏好。

## 需求描述

- `getDeviceType()` 返回 `desktop` 或 `mobile`，手机和平板均归为移动端；`isMobileDevice()` 提供布尔快捷判断。
- 移动端在「设置 → 界面」显示「横屏模式」，默认关闭，开启或关闭立即生效并记忆。
- 偏好贯穿开始页、联机大厅和游戏，不随新游戏、死亡、切换角色或房间重置。
- 关闭横屏模式恢复跟随设备方向，不强制锁定竖屏。

## 设计方案

### 设备识别

`src/platform/device.ts` 综合 UA Client Hints 的 mobile 标志、移动平台 UA，以及 iPadOS 桌面 UA 的 Mac 平台与多点触控特征。不会把电脑窄窗口或 Windows 触屏电脑当作手机，也不会因手机横屏切换分类。服务端缺省为桌面，客户端挂载后识别，避免 hydration 差异。浏览器隐藏或伪造设备信息时无法保证绝对准确。

### 全局存储

独立键 `island.display.landscape` 使用 `on/off` 持久化至 localStorage；同页面通过订阅同步设置与显示控制器。作用域为当前浏览器、当前站点，不包含在角色存档内，不改变 `SAVE_VERSION`。清理站点数据会重置偏好；存储不可用时仅保留当前会话的选择。

### 横屏控制

`MobileDisplay` 在阶段路由外提供统一的 `game-viewport` 容器。`LandscapeController` 直接响应玩家设置：竖向窗口开启横屏时，将容器宽高交换并顺时针旋转 90 度；窗口已为横向时直接铺满，避免二次旋转。关闭后立即恢复窗口布局。不调用浏览器方向锁定、全屏接口，也不要求系统开启自动旋转。

窗口尺寸变化时重算逻辑宽高，已有 ResizeObserver 自动更新画布与相机。开始页、联机大厅、游戏 HUD 和弹窗共用容器；开关不卸载游戏、不重建联机连接。响应式尺寸使用 `--game-vw/vh`，尺寸与方向断点使用命名容器查询，安全区随旋转映射。

`displayCoordinates.ts` 统一转换游戏坐标与元素矩形：摇杆移动、背包拖拽浮层、Buff/物品提示、奖励飞行动画、拍照手势、转轮和选择器边缘滚动使用逻辑坐标；DOM 命中检测继续使用真实屏幕坐标。云存档弹窗也挂载到游戏容器内。

### 联机

房主与客人独立识别本机设备、读取本机偏好，仅改变各自显示方向。游戏权威状态、动作上行、快照和事件同步均不变，不广播个人显示设置。
