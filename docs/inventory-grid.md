# 格子背包与地面掉落物

## 背景

原背包是「资源计数表」(四种资源各一个数字),背包面板里混合展示资源与合成列表,无法体现道具的个体、描述与丢弃。需要改为手机游戏常见的格子制背包,并支持把道具丢到地上。

## 需求描述

- 点击背包按钮打开格子背包面板(面板里不再有合成功能,合成仍由左侧手搓卡片触发)。
- 背包按钮采用按下即打开，触屏与鼠标的后续点击不重复切换；键盘、辅助技术保持可用。开关仅影响各端本地 UI，单机、房主和客人一致，不新增网络动作或改变背包权威结算。
- 默认 10 个格子;相同道具自动叠加(单格上限 20);装备背包类道具后可扩容。
- 点击有道具的格子显示道具描述,并提供操作:
  - 丢弃:将一个该道具丢到玩家附近地上,走近后可自动拾回;
  - 使用:食物道具可点击使用(开始进食),并自动关闭背包。

## 设计方案

### 物品格名称显示

背包与设施共用 SlotItemName 和 SlotItemCount，统一名称滚动及右上角数量展示。背包维持 52×52px，储物设施格维持 48×48px；各面板保留原触控行为。

### 手机格子与工具分类

- 背包顶部仅保留物品、制作、工具、角色四个页签，设置仍从游戏右上角进入。
- 物品格保持原来的 52×52px、五列与 8px 间距；底部常驻单行 11px 名称，短名称居中静止，溢出的长名称按实测宽度缓慢往返滚动，两端停留。系统要求减少动态效果时改为省略显示。数量独立放在右上角的浅底角标，点击格子后在详情区显示完整名称和数量，不依赖悬停或长按。
- 拖动按实际格子矩形命中，适配窄屏、面板滚动及横竖屏。点选、双击使用、拖动整理和拖出丢弃沿用原交互。
- 剪刀沿用永久工具系统：三级工作台制作后进入工具页、不占物品格、不能重复制作或丢弃；GM 领取、旧掉落拾取和旧木箱取回也解锁工具。剪刀只有一个等级。
- 保持存档版本和 shears ID 不变，工具字段缺省为未拥有；读取旧档时将原物品格里的剪刀归入工具并清空该格，箱内旧剪刀在取回时归入工具。


- `src/game/systems/Inventory.ts`:重写为格子制。`InventorySlot = { kind, count } | null`,`capacity` 默认 10(常量 `DEFAULT_CAPACITY`),`setCapacity` 只扩不缩。`add` 先叠加已有格再占空格,返回实际放入数(背包满则放入失败);`remove` 从后往前扣(保留靠前的格子);`count(kind)` 汇总;`snapshot()` 供 UI 渲染。
- `src/game/systems/Items.ts`(新增):道具静态定义 `ITEMS`,含名称、图标、描述;后续新道具在此登记。
- `src/game/systems/DropSystem.ts`(新增):地面掉落物系统。每个掉落物是低面数八面体网格,按道具着色,在玩家附近随机偏移落地,旋转 + 悬浮动画;丢弃后 0.8 秒内不可拾取,玩家走近(1.3 距离内)自动拾回背包,背包满则留在地上。
- `src/game/Game.ts`:
  - `HudSnapshot` 新增 `slots`(格子快照)与 `capacity`;原有的 wood/gravel/stone/berry 计数改为由格子汇总,继续供手搓/进食卡片判断材料。
  - 新增 `dropItem(kind)`(丢弃一个到地上);`eatFood(kind?)` 支持指定食物种类(背包「使用」按钮),不带参数时仍吃背包最前面的食物。
- `src/ui/Backpack.tsx`:重写为格子面板。5 列格子网格,点击有道具的格子选中并在下方显示名称、数量、描述与「使用/丢弃」按钮;使用食物后由外层关闭背包。背包入口采用手绘 SVG 与浅色半透明圆角按钮，触控反馈及横竖屏布局见 `hud-design.md`。
- 合成消耗(`Crafting`/`WorkbenchSystem`)与进食判定(`EatingSystem`)从读取计数表改为 `inventory.count(kind)`。

## 迭代记录

### 背包整理与拖出丢弃

- 背包「物品」页标题行右侧新增「整理」按钮:`Inventory.sort(weight)` 先把同类道具合并到一格,再按 `itemSortIndex`(物品分类 `ITEM_CATEGORIES` 与类内登记顺序,未登记道具排最后)从前往后排列,空格沉底。
- 拖拽道具到背包面板外松手 = 丢弃整格道具到地上:`Backpack.tsx` 在拖动松手时若未命中任何格子且指针在面板矩形外,调用 `onDropItem(kind, count)` 丢弃整格(复用既有丢弃链路,掉落物可走近拾回)。
- 联机:整理走 `Game.sortInventory`(客人经动作 `sortInventory` 上行,房主权威结算后经快照回流);拖出丢弃复用既有 `dropItem` 动作。

### 丢弃数量步进支持长按连发

- 丢弃数量的 −/+ 步进按钮改为 `StepButton` 组件:点按一次 ±1;长按进入连发,连发间隔从 160ms 随按住时长逐渐加速到 45ms,步进在按住 0.8s 后升为 ±5、1.6s 后升为 ±10,松手/移出即停。数量仍被钳制在 1 与当前持有数之间。

### 制作页全量展示与排序

- 背包「制作」页不再按条件隐藏手搓配方:全部手搓配方始终列出,仅已拥有的手搓工具(木斧/木镐)不再出现。
- 原隐藏条件(材料不足、工具已拥有、装备评分不更高、已有工作台/火堆)转为「不可制作」状态:按钮置灰,文案按原因显示「材料不足」或「已拥有」;材料行改用 `MaterialRequirements`,缺口红色标出并前置。
- 排序:可制作在前 → 当前任务配方置顶(`questRecipePriority`)→ 手搓进程序(`promptPriority` 升序,与场景快捷卡弹出顺序一致)→ 同序号按配方定义序稳定排列。
- 纯客户端展示逻辑,数据全部来自既有 HUD 快照;制作动作与联机链路(`craftTool` 上行、房主结算)不变。场景手搓快捷卡的弹出/抑制规则不受影响(见 `prompt-cards.md`)。
