# 围栏与围栏门

## 背景

玩家需要在岛上圈出一块封闭区域(养动物、围院子)。原有放置物都是自由坐标(玩家脚下),无法保证对齐,难以围出没有缝隙的闭合图形;动物也没有任何碰撞,即使围起来也会穿过去。

## 需求描述

- 二级工作台可制作:1 木头 → 2 个木围栏;1 石头 → 2 个石围栏;2 木头 → 1 个围栏门。
- 围栏之间自动连接,玩家能方便地围出没有缝隙的正方形封闭区域。
- 围栏能挡住玩家和动物(兔/羊/野牛/狼/熊/蟹);围栏门玩家可通过,动物不会开门。
- 围栏/门可用铲子挖回道具,可存档。

## 设计方案

### 网格顶点吸附 + 自动连接

- 围栏网格边长为 1。围栏柱吸附在整数格点 `(gx, gz)` 上,背包「使用」时落在玩家面前约 0.9 处最近的格点。
- 每根柱子检查四个相邻格点(±1, 0 / 0, ±1)是否有围栏或门,自动向这些方向伸出两根横杆(各覆盖半格),相邻柱合起来即无缝;放置/挖除后刷新自身与四邻的网格。
- 玩家沿正方形边走一圈逐个放置,天然闭合,无需任何对齐操作。

### 围栏门

- 门占一条格点边(东西边或南北边),放置时吸附到玩家面前最近的边;该边已有门或已有围栏横杆(两端都有柱)时不可放。
- 门框两端立柱,门扇绕一端立柱旋转;玩家靠近(约 1.25)自动开、走远自动关,无需任何按钮,动物不会开门。

### 阻挡

- 围栏连接与「关着的门」构成阻挡线段集合(`FenceSystem.segments`)。
- 玩家:接入 `ObstacleSolver`,移动时被线段推出(`resolveCollision`,点到线段推挤)。
- 动物:`Wildlife.isGrass` / `Crabs.isSand` 可走性判定注入 `isBlocked(x, z)` 回调,围栏线段附近视为不可走;动物寻路本来就是「直行失败试切线」,围栏闭合时切线也失败,即被圈住。

### 挖除与存档

- 手持铲子靠近站定自动拆(2 次命中,精致铲 1 次),变回对应道具入包。
- 存档:`fences: {x, z, kind}[]`、`fenceGates: {x, z, dir}[]`(门的开合状态由玩家距离即时推导,不入档);`SAVE_VERSION` 升到 21,旧档丢弃。

### 相关文件

- `src/game/entities/Fence.ts` / `FenceGate.ts`:程序化建模(木柱/石柱/横杆/门扇),连接变化时重建。
- `src/game/systems/FenceSystem.ts`:放置、连接刷新、阻挡线段、自动门、挖掘、快照。
- `Player.ts`(`setObstacles` 支持多个阻挡源)、`Wildlife.ts` / `Crab.ts`(注入 `isBlocked`)、`Game.ts`(接线)。
- `Inventory.ts` / `Items.ts` / `Crafting.ts` / `DropModels.ts`:道具 `fenceWood` / `fenceStone` / `fenceGate`、配方(均 `minBenchLevel: 2`)与掉落模型。
- `Backpack.tsx` / `GameplayUI.tsx`:背包「使用」分发。


## 迭代记录(工具循环并入)

2026-09-09:围栏/围栏门并入「限定位置自动安放」的统一工具循环(`docs/autoplace.md`):木围栏、石围栏、围栏门在背包里各占一格循环条目,图标用各自物品图标,手持模型改为真实建模缩小(替代原静态捆栏模型),放置/预览/自动安放逻辑仍由 `FenceSystem` 自行结算(网格顶点/边吸附、门 5 秒安放时长不变),远程玩家经 `PlayerState.placeKind` 看到手持种类。

2026-09-09(迭代):围栏的放置体验整体并入统一设施体系(`docs/autoplace.md` 的设施注册表):落点选择(接线优先)、幽灵预览(横杆按邻居显隐)、门朝向与 5 秒安放时长经 `FacilityDef` 的 `target`/`onPreview`/`holdTime` 委托回 `FenceSystem`;`FenceSystem` 只保留围栏世界状态、放置/挖除结算与存档,删除其独立的选中入口、预览与自动放置;联机放置上行统一为 `useFacility [kind]`。围栏网格、连接规则、门开合与阻挡不变,存档不变。

2026-09-12(迭代):修复围栏幽灵预览与实物不一致——删除预览专用的平行建模(`makeFenceGhost` 的木柱整杆模型),预览改为复用实物的 `buildFenceMesh`(按 `FenceKind` 区分木/石柱与横杆规格,横杆命名 `rail-<dir>` 供按邻居显隐,预览态跳过网格合并);同时围栏预览旋转固定为 0(与实物一致,此前跟随玩家朝向旋转会让横杆显隐方向与实际连接错位)。

2026-09-12(迭代):幽灵预览补全「另一半连接」——预览柱视为已放置,相邻已有柱按同一套连接规则(`connsWith` 叠加虚拟格点)补出朝向预览柱的横杆;补杆以幽灵材质(`Facilities.ts` 的 `previewGhostMaterial`,与安放系统预览同款观感)叠加在真实网格之上、不投影,真实网格不动;落点变化不再是邻居、或收起/切换预览(经 `FacilityDef.onPreviewHide`)时移除补杆。

2026-09-12(迭代):围栏与门之间不伸连接横杆(门带自带门框,围栏朝门出杆表现错误)——连接判定改为仅柱对柱,实际放置、预览横杆显隐与幽灵补杆统一生效;门的落位查重(`gateAt`)保留,只是不再参与连接。旧档读取时按新规则重建连接,存档结构不变。同时围栏柱的落点校验(`vertexValid`)增加门带覆盖判定:门带占的三个顶点(两端门框柱与中间门扇)都不允许再立围栏柱,预览会显示为不可放。

## 静态部件绘制合并
围栏静态柱/横杆在创建和连接重建时合并为单网格，颜色使用顶点色，保留投影；门仍独立运动。详见 [绘制优化](render-batching.md)。
