# 拾取飘字与本地存档

## 背景

1. 玩家获得物品(采集、制作、烹饪、钓鱼、捡回掉落物等一切入包行为)时缺少即时反馈,希望在角色头顶飘过物品图标与数量。
2. 荒岛生存进度一次性,刷新/关闭页面即丢失。希望利用浏览器 localStorage:只要没死亡,下次进入游戏继续上次的进度(位置、背包、工具、世界状态)。

## 需求描述

- **拾取飘字**:任何道具进入背包时,在玩家头顶生成一条「图标 ×数量」的提示,向上飘动并渐隐消失。
- **本地存档**:游戏运行期间自动保存到 localStorage;未死亡退出后再次进入,自动恢复同一座岛(地形与资源点布局一致)及玩家全部进度;死亡则清档,下次重新开始。

## 设计方案

### 拾取飘字与入包飞行

- `Inventory.add()` 成功放入后触发 `onAdd(kind, count)` 回调(实际放入数量)。
- `Game` 把入包项先缓存到 `pendingPickups`,帧末统一处理:每件道具(同种最多 3 个模型)用掉落物造型(`DropModels.makeDropModel`)从飞行起点沿二次贝塞尔曲线飞向玩家后背,错峰出发、途中自转、临到达时缩小到消失(表现层模块 `fx/ItemFlyFx`,终点每帧跟随玩家)。
- 全部模型到达后,才把玩家头顶世界坐标投影为屏幕坐标,通过 `onPickup(toast)` 回调抛给 React 层合并飘一条提示(道具图标+名称×数量)。
- 飞行起点:采集为资源点位置(`CollectSystem.onYield` 上报),捡拾掉落物为掉落物位置(`DropSystem.getNearby` 返回 `position`);其余来源(合成产出等)兜底为玩家身前。客人端入包由 HUD 快照差额触发,起点短时保留(约 1 秒)等待快照回流。表现完全本地,不影响权威结算。
- `GameplayUI` 维护一个 toast 列表(带自增 id),渲染为绝对定位元素,用 CSS 动画 `pickup-float`(globals.css)上飘渐隐,1.4 秒后自动移除。

### 本地存档(SaveSystem)

- 存储键 `island.save.v1`,带版本号,解析失败/版本不符视为无存档。
- **兼容策略**:普通内容迭代保持 `SAVE_VERSION` 不变。新增字段应优先设为可选并在恢复时提供默认值；道具、资源、配方和建筑使用稳定的持久化 ID。只有旧数据已无法安全解释的破坏性变更才升级版本并放弃旧档，不维护跨破坏性版本迁移。
- **世界恢复**:地形仍由 `terrainSeed` 重建；自然资源首次开局随机生成，之后每个资源点以完整状态（种类、坐标、朝向、采集/生长状态）直接入档，不再依赖资源种子复算布局。
- **保存内容**:地形种子、玩家位置与手持工具、生存四维、背包格子与容量、已解锁工具、昼夜时刻、全部资源点完整状态、火堆(位置+燃料,灰烬不存)、工作台位置、地面掉落物。
- **保存时机**:每 5 秒自动保存;`Game.dispose()`(退出游戏)时再保存一次。
- **恢复时机**:`Game` 构造时读取存档,用地形种子生成岛形后,统一在 `applySave` 按完整列表重建资源与恢复各系统状态。
- **清档**:检测到死亡的瞬间 `SaveSystem.clear()`,下次进入生成新岛。
- 各系统暴露 `snapshot()/restore()`:Inventory(load)、Props、CampfireSystem、WorkbenchSystem、DropSystem;DayNightSystem 暴露 `time` 存取器。
