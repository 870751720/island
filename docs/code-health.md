# 代码健康

## 背景

项目已经按核心循环、实体、玩法系统、网络、世界和 React UI 分目录，但持续增加玩法后，少数聚合文件承担了过多职责，跨层类型依赖也逐渐形成。健康优化只调整代码组织、依赖方向与可维护性，不改变玩法、交互、存档数据或联机协议。

## 需求描述

- 保持现有单机与 WebRTC 房主权威联机行为不变。
- 识别模块边界、超大文件、循环依赖和明显的类型逃逸。
- 优先实施可由 TypeScript 与生产构建验证的低风险重构。
- 后续新增玩法继续落在对应 system/entity/world 模块，避免扩大聚合入口。

## 设计方案

### 当前评估

- 整体分层合理：`src/game` 已按 `core`、`entities`、`systems`、`net`、`world`、`fx` 拆分，UI 也与游戏代码分目录。
- 主要热点是 `Game.ts`：它同时负责场景装配、会话编排、网络同步、存档、输入路由、HUD 快照和大量玩法门面调用。它应长期收敛为组合根，但不适合一次性大拆，以免改变游戏循环时序。
- `Wildlife.ts`、`DropModels.ts`、`Props.ts` 和 `GameplayUI.tsx` 也偏大，后续应按“状态/规则、模型工厂、生命周期协调、面板状态”逐步拆分。
- 审计未发现 `any`、`@ts-ignore`、`TODO/FIXME/HACK` 等明显类型逃逸或遗留标记。
- 原依赖方向存在问题：网络协议和多个 UI 组件从 `Game.ts` 获取纯快照类型，而 `Game.ts` 又从 UI 组件获取生命数值类型，造成实现模块参与类型契约和跨层反向依赖。

### 边界规则

- 跨游戏、网络和 UI 层传递的数据结构统一放在 `src/game/GameContracts.ts`。
- `Game.ts` 只实现运行时协调，可为兼容已有调用方重新导出契约，但内部模块应直接依赖契约文件。
- 契约模块只允许类型导入，不产生运行时依赖，不改变序列化字段和网络消息格式。
- 大文件按独立职责渐进拆分；每次拆分保持调用顺序、默认值和房主/客人分支不变，并通过类型检查与生产构建。

## 迭代记录

### 2026-09-09

- 完成代码体量、分层、坏味道与跨层依赖审计。
- 新增 `GameContracts.ts`，集中 `HudSnapshot`、`MapSnapshot`、`PickupToast` 和 `VitalLevels`。
- 网络协议、网络会话和 UI 组件改为直接依赖契约模块，解除 `Game.ts` 与 `Protocol.ts`、`VitalWarn.tsx` 间不必要的循环/反向依赖。
- 保留所有字段、默认值、存档版本和联机协议行为，不涉及功能变化。
- 将设施按钮劫持与铲子优先级规则从 `GameplayUI.tsx` 抽为纯函数，以具名字段取代九个位置布尔参数，降低参数错位风险并保留火堆优先不可挖的既有行为。
- 统一设施面板读取背包快照数量的实现，移除四份重复函数和两处重复归并逻辑。
- 将 HUD 默认快照从生命周期组件抽为独立工厂，每次挂载创建新的嵌套对象与数组，缩小 `GameplayUI.tsx` 并避免初始化状态共享可变引用。
- 将八类设施面板的打开状态、离开范围清理与死亡清理统一到专用 hook，消除重复 effect，并补齐酿酒桶面板的死亡状态清理。
- 将手持选择器的工具解锁、套索与可放置道具条目组装抽为纯视图模型函数，移除 JSX 内的立即执行函数并保持原有排序规则。
- 将捡回、进食与手搓提示卡的互斥优先级抽为纯函数，移除第二处 JSX 内立即执行函数，并保持“捡回 > 进食 > 手搓”的既有顺序。
- 将 `Game` 的双帧延迟创建、启动、销毁、HUD 回流和角色头顶表现桥接集中到 `useGameLifecycle`，使 `GameplayUI` 回归界面编排职责，并保留单机/房主/客人的初始化分支。
- 增加统一的 `npm run typecheck` 与 `npm run check` 工程脚本，固定“类型检查 + 生产构建”的本地验收入口，避免依赖临时命令。
- 建立联机动作名到参数元组的统一类型表，客人端动作发送与房主动作注册表共享约束，在不改变线上消息结构的前提下提前发现动作名拼写、缺失注册和参数顺序错误。
