# 设施公共架构

## 背景
设施的安放、背包入口、回收提示和实体生命周期需要共同的接口，避免新增物品后在多个展示名单中重复登记。火把是照明设施，不属于神龛。

## 需求描述
- 全部 51 种背包设施使用统一安放入口，手机背包的使用按钮和双击使用一致。
- 回收名称来自实际目标，显示具体门、床与工作台等级，以及正确的道路和神龛物品名称。
- 净化器提供回收名称与进度，熄灭火堆持铲时保留工具按钮。
- 保留房主权威、原有物品 ID、旧档和联机兼容性。

## 设计方案

### 分层与职责
- `entities/Facility.ts`：设施实体基类，只包含物品身份、场景节点、更新和资源释放契约。
- `entities/Torch.ts` / `entities/Shrine.ts`：平级设施实体；前者负责火焰和照明，后者负责神龛模型与表现。
- `systems/FacilitySystem.ts`：可整件回收设施的通用实现，包含占格、安放校验、扣料、按玩家回收状态、释放、保存、恢复和增量应用。切换回收目标重新计时，清空世界释放动作与资源。
- `systems/AmbientFacilitySystem.ts`：将火把和神龛工厂装配到公共系统，`ShrineEffects` 单独查询祝福。通用生命周期不判断具体神龛效果。
- `systems/FacilityRegistration.ts` / `Facilities.ts`：所有可放置设施唯一的行为注册入口，必填回收来源；模型预览、放置规则和特殊效果仍由具体模块提供。
- `systems/FacilityInteraction.ts`：统一回收交互契约。设施注册时自动收集来源，同一系统只查询一次；名称和进度由持有实际目标的系统返回，展示层只消费结果。
- 背包和手持面板共享 `HudSnapshot.placeables`，不再维护第二份可使用设施名单。重复注册同一物品立即报错。

### 全部设施核对范围
| 设施组 | 公共能力与保留的特有行为 |
| --- | --- |
| 火把、五种神龛 | 共用设施实体基类、生命周期；火把照明与神龛祝福分离 |
| 木箱、铁箱、鱼护、食料桶 | 安放入口和回收契约统一；保留容器内容、返还和自动收存/取食 |
| 饵料桶、酿酒桶、冶炼炉、纺织机、烹饪台 | 统一入口和回收提示；保留各自产能、材料、燃料和生产同步 |
| 宠物窝、海水净化器 | 统一回收契约；保留伙伴及海岸地形限制 |
| 火堆、熄灭的火堆 | 共用安放入口；仅熄灭后可回收为熄灭的火堆，UI 根据燃烧状态判断 |
| 木/石围栏、木门、石门 | 统一回收目标名称；保留格点连接、门朝向与自动开合 |
| 木板路、碎石小路 | 背包入口来自注册表；保留贴地批次渲染和移动加速 |
| 一至三级床、一至四级工作台 | 回收提示读取目标等级；保留睡眠、升级和制作 |
| 三类树种、十二类作物种子 | 统一背包入口；树木保留采集系统，作物铲除由土壤系统提供 |
| 浆果丛、灌木丛、草丛、蚯蚓窝 | 统一安放入口；挖回与采集仍由资源系统处理 |
| 土壤、野生兔子洞 | 非背包设施，提供同一交互契约；开垦、铲作物和洞穴塌毁仍独立结算 |

有容器、升级、邻接或生产状态的系统不强行继承只存位置的 `FacilitySystem`；它们通过同一注册定义和回收接口接入，专有状态保留原有保存与复制逻辑。新增类似火把的整件回收设施可直接复用公共生命周期；新增特殊设施必须在注册定义中明确回收来源，不能往 HUD 添加设施分支。

### 存档与联机
`shrines` 是保留的存档/世界同步字段名，不是火把的运行时类型。该段仍保存原有 `kind/x/y/z/id`，实体 ID 前缀继续使用 `shrine_`；无 ID 旧档仍由既有 ID 服务补齐。`SAVE_VERSION`、网络协议版本保持不变。

房主结算安放扣料和回收返还，客人通过既有动作上行及世界增量获取结果；提示经玩家 HUD 回流并继续做进度插值。各端独立更新实体动画和光源，删除快照释放对应光源。不新增事件补播。

### 图鉴与验证
所有设施图鉴显示统一安放方式；原有回收条件、配方、解锁和掉落规则不变。回归脚本 `node scripts/test-facilities.mts` 覆盖全设施注册与背包入口、回收来源漏接、具体目标名称、占格拒绝、火把光源释放、旧档恢复和客人增删快照；照明预算另由 `test-flame-lighting.mts` 检查。手机运行时与实际联机由用户本地验证。
