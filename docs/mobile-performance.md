# 手机性能与发热

## 背景
玩家反馈手机长时间运行发热、卡顿。代码中存在资源邻域重复查询、临时快照分配、联机重复采样和天气缓冲全容量上传，增加每帧及定时广播的负担。

## 需求描述
- 不限制帧率，不改变游戏循环、渲染频率和动画精度。
- 保留抗锯齿、原有 DPR 上限 1.75、阴影分辨率与过滤、材质、粒子数量和动画。
- 通过减少重复计算、临时对象与无效 GPU 数据上传改善运行开销。
- 房主权威结算、客人预测与同步、存档保持兼容。

## 设计方案
### 资源空间查询
`Props` 按原有 8 米格子缓存九宫格邻域成员，同格子的碰撞、放置、采集和触碰查询复用数组。缓存只保留实体引用，阻挡、成熟状态、距离和碰撞半径仍在每次查询时实时判断，不缓存查询结论。增加、移除、清空资源时立即失效，覆盖单机、房主和客人快照更新路径。最多缓存 128 个邻域，避免探索导致内存无限增长。

### 任务条件查询
工作台最高等级、是否存在毛皮掉落、是否存在燃烧火堆直接查询对应系统。每次任务检查只读取一次共同条件，不为条件判断生成整个存档快照，也不按玩家重复生成火堆快照。任务检查频率和结算语义保持不变。

### 联机广播
房主先清理超时客人，再为当前广播拍生成一份量化的玩家、天气、战斗动物、普通动物及环境生物状态。所有客人复用本拍采样，每位客人的差分基线、输入确认、首次全量、周期恢复及个人 HUD 保持独立。无已接入客人时不采样。25Hz/10Hz/5Hz 广播节奏不变。

### 天气数据上传
雨丝、雪花和飘叶仍分配原有最大容量，但每帧通过更新范围只上传当前实际绘制的前缀。首帧由 Three.js 完成缓冲分配；横竖屏变化时使用新的有效数量，下一可见帧上传完整有效前缀。雨丝使用动态缓冲提示，与雪花和飘叶一致。

竖屏基准数量为最大容量的五分之一，稳定运行时这三类缓冲的更新数据量约减少 80%；这是数据上传量的推算，不代表整体 GPU 开销或发热降低 80%。粒子数量、坐标、轨迹、透明度、材质与绘制次数保持不变。

### 分区实例化与模型缓存
`ModelInstances` 按 16 米空间格和模型模板管理 `InstancedMesh`。同一区域中，相同模型的每个材质/阴影部件共用一次绘制；保留原几何、材质、季节 shader、投影和接收阴影标记。空间格保留局部剔除粒度，避免整张地图合成一个大网格。

- 树木按树种、生长阶段、树桩和挂果状态缓存模板；石头、铁矿、碎石、陨石、草和灌木也复用模板。实体保留独立的根变换、碰撞坐标和稳定 ID，风摇、触碰弯曲、受击晃动、采集缩放和显隐继续按原逻辑逐帧计算。
- 围栏按木/石种类及四方向连接组合缓存模板，连接变化只切换实例所属批次。幽灵补杆和自动开合的门继续独立绘制。
- 农田分为土床/土垄模板和土坷垃基础球体模板，原有按坐标生成的土坷垃位置、尺寸、扁平比例和颜色保持不变。密集农田每个空间格约两次主体绘制（不包含作物），不再按土壤格逐一提交。
- 围栏、农田为静态实例，注册时保存矩阵，未变化的批次不逐实例扫描或上传；固定节点关闭局部矩阵自动重算。动态资源在每次绘制前读取最终变换，只有矩阵、显隐或成员变化的批次上传有效前缀。实例容量按需翻倍；变换或成员变化后重算包围球，供主相机和阴影剔除使用。
- 模板按系统生命周期持有，单个实体移除只移除实例；空批次释放实例缓冲，退出游戏统一释放模板几何体和材质。树木切换已有外观时不再重新拼装和合并几何体。

保留浆果丛、蚯蚓窝的独立子部件显隐实现。动物死亡时会转为透明材质并渐隐，直接合并可能改变透明排序，因此本方案保留动物原有绘制方式。

### 每帧界面分配
头顶作业文字、气泡、任务提示、狗狗表情和生存提醒的投影复用两个向量。自言自语文字未改变时不重复替换 DOM 文本，继续每帧定位，不降低 UI 或动画更新频率。

### 验收
开发执行 TypeScript 检查和生产构建，不运行开发服务器或浏览器测试。线上由用户在同设备、同存档、同视角、同天气下对比 GM 性能报告与长时间运行体验；实际帧率与温度改善需实机确认。不新增存档字段，不改变 SAVE_VERSION。

实机重点覆盖：三种树的风摇、摘果与再生、生长和砍桩；草和灌木采集/再生与碰触；矿石采空；围栏增删后的连接、幽灵预览及门开合；不同位置土壤的外形与铲除；冬季积雪、拍照视角和横竖屏下的阴影与剔除；客人加入、重连及房主/客人双方建造、采集后的同帧画面。合批收益取决于同屏同类物体密度，空间格边缘可能提交更多不可见三角形，不将绘制次数的减少等同于温度或帧率的固定提升比例。
