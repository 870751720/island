# Game 模块渐进拆分

## 背景

`src/game/Game.ts` 同时承担游戏装配、玩法入口、联机协调和表现层调度。持续在单一文件内扩展会提高修改冲突与回归风险，因此采用保持公开接口稳定的渐进拆分方式。

## 需求描述

- 不改变玩法、触屏交互、存档格式或联机协议。
- 每次只迁出职责边界清晰、可独立类型检查的模块。
- `Game` 继续作为 UI 和联机层使用的门面，避免调用方随内部拆分反复变化。
- 每一步均可独立提交和回退，全部完成后再部署。

## 设计方案

当前边界如下：

- `GameConfig.ts`：游戏级时间、距离和表现参数。
- `GameTypes.ts`：构造选项及游戏编排层内部共享类型。
- `presentation/PickupPresentation.ts`：拾取来源缓存、道具飞行动效、同帧提示合并与屏幕投影。
- `presentation/HudSnapshotBuilder.ts`：汇总玩家、设施、环境与增益状态，生成本地及联机定向 HUD 快照。
- `presentation/InteractionIndicatorBuilder.ts`：按原优先级归并玩家动作、设施动作与自动换工具提示。
- `presentation/GameCameraController.ts`：统一跟随相机、拍照模式手势、太阳阴影跟随与画面读回。
- `systems/ToolCycle.ts`：工具循环候选和可放置物品排序策略。
- `systems/FacilityInteractionController.ts`：统一设施 UI 命令的客人端上行和房主权威结算。
- `systems/PlayerCommandController.ts`：统一背包、装备、制作与工作台命令。
- `systems/SessionSaveCodec.ts`：单玩家会话的存档恢复与快照编码。
- `systems/DeathReportBuilder.ts`：死亡战绩汇总与局外求生心得结算。
- `systems/WorldSaveCodec.ts`：世界设施与环境状态的恢复和快照映射，保留联机权威生成规则。
- `Game.ts`：保留生命周期装配、公开门面、房主权威结算与跨系统流程编排。

联机行为保持原有方向：客人动作继续上行至房主权威结算；拾取事件仍由房主广播，客人只补播其他玩家表现；本地玩家的拾取表现继续由 HUD 差额触发。拆出的模块不引入新的持久化字段或网络消息。

后续拆分优先选择网络快照编排。涉及多个系统的权威事务继续留在 `Game`，直到已有显式上下文对象可以承载依赖，避免用大而宽泛的依赖接口机械搬运代码。

## 迭代记录

- 第一阶段：迁出配置与共享类型、拾取表现协调、工具循环策略；保持 `Game` 的公开 API、存档版本和网络协议不变。
- 第二阶段：迁出玩家会话存档编解码、HUD 快照构建及死亡报告结算；存档结构、缺省恢复规则和 HUD 网络载荷保持不变。
- 第三阶段：迁出头顶交互提示决策链和世界存档编解码；保持提示优先级、设施字段及客人端非权威生成规则不变。
- 第四阶段：迁出相机与拍照表现协调；拍照模式仍仅冻结单机模拟，联机房主和客人继续运行权威世界。
- 第五阶段：迁出木箱、加工设施、火堆和烹饪台的交互命令；保持原动作名、参数和定向提示。
- 第六阶段：迁出背包、装备、制作与工作台命令；`Game` 保留公开门面，UI 和 `Actions.ts` 调用方式不变。
- 存档策略调整：`SAVE_VERSION` 升至 32，旧版本直接弃档；删除弹药归一化、缺失设施默认值及蚯蚓窝补撒等旧档兼容分支。
