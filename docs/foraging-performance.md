# 动物觅食寻路性能

## 背景

排查范围为 dc60e8ac9b54bedc4633888feeacab7410e58680 到 ab964fb，共 82 个提交。玩家反馈单机开始流畅，游玩一段时间后严重卡顿。

85689ac 扩大驯养活动范围并改用 A* 时，移除了旧实现中“接近目标才检查最终连线”的距离条件。初始直线被围栏阻挡后，最多 900 个搜索节点都会再次以 0.15 米间距扫描通往远处食物的长线；目标不可达时，动物会重试，多个候选与动物进一步放大主线程计算。

## 需求描述

降低障碍物附近不可达食物的寻路尖峰，保留活动范围、自然食物优先、储粮阈值、碰撞约束和存档兼容性。

## 设计方案

- 无障碍时保留初始直达检查；直达失败后继续 A*，仅在距离目标小于两个网格步长时检查最终连线。
- 保留每次搜索 900 节点上限及逐段碰撞校验；不放宽围栏、地形、牵绳和家园边界。
- 单机与房主共用修复后的权威寻路；客人继续接收动物姿态，不增加消息或持久化字段。
- 图鉴中的玩法、名称和获取条件均未改变，无需修改条目。

## 验证与结论边界

`node scripts/test-food-path-budget.mts` 使用动物位于 (-28, 0)、食物位于 (28, 0)、30 米活动圆内有贯穿围栏的场景。修复前一次不可达搜索触发 95,552 次 allowed 回调，修复后 5,253 次，减少约 94.5%；这代表碰撞判定次数，不代表手机帧率提升比例。测试同时验证有出口时路径仍可达且各段不穿墙。

`node scripts/test-husbandry-care.mts` 覆盖六小时饲养模拟、自然资源优先、储粮阈值、远距离绕行和封闭围栏。

已核查新增火光、设施逐帧更新、音频采样生命周期和云备份调用：点光源仍固定为六个，光晕仅增删时重建，新增采样结束后断开节点，首次云备份不是周期上传。尚无真机性能采样证明这些是本次卡顿原因。已确认寻路回退，但不能认定它解释全部玩家症状；若无觅食动物仍卡，需进一步对比卡顿前后的本机性能面板与同档重进结果。

## 实际存档复算

用户提供的第 173 天存档包含 1,864 个资源点、43 只保存动物（5 只已驯养且正在觅食）、240 个围栏柱、14 个围栏门、23 个火把；饵料桶为空。原始存档仅保存在被 Git 忽略的本地诊断目录，不提交、不覆盖云端。

用实际地形种子、资源位置、围栏恢复正式 Props/FenceSystem/Wildlife，固定随机序列和玩家存档位置，按每秒 30 次推进两分钟。恢复后的动物总数为 69（包含不写入家族存档的其他动物），四个 30 秒窗口动物数均稳定；更新资源、围栏与动物的桌面 Node 平均耗时约 0.4～0.5 ms/次，没有随运行时间增长。寻路修复前后，各窗口碰撞调用次数完全一致：25,550 / 25,437 / 26,612 / 27,405。

此模拟不执行 WebGL、React、音频和真实玩家操作，奶瓶图标用无纹理 Sprite 替代，时间按固定流速推进。结论是静止存档的这部分 CPU 逻辑未复现故障，不能用人工寻路用例证明实际卡顿已解决。还需原设备的卡顿前后帧率、逻辑 CPU、渲染提交、绘制次数和几何体/纹理计数，区分渲染压力、资源累积和操作触发的负载。
