# 动物觅食寻路性能

## 背景

排查 dc60e8ac9b54bedc4633888feeacab7410e58680 到 ab964fb 的82个提交后，发现扩大觅食范围的改动增加了候选长线检测与A*工作量。真机第80天报告共6.64秒、292帧，最慢CPU帧525.8ms，其中动物AI占510.3ms，WebGL提交10.2ms；其余四次明显尖峰也集中于动物AI。报告确认了动物模块的阻塞，原分段尚不能直接区别寻食、补刷和其他动物行为。

## 需求描述

动物食物搜索统一限制为当前位置水平半径15米，首次驯养与日常觅食共用；保留30米家园活动圈、3米桩绳限制、自然食物优先、储粮阈值和消费校验。限制单帧寻食工作量，避免多个动物的重试集中阻塞主线程。

## 设计方案

- FOOD_SEARCH_RADIUS=15作为唯一运行时口径。草丛、灌木、浆果丛、地面适配食物和食料桶均在选择阶段校验距离；超过15米不选中。
- 所有权威动物共用ForagingSearchQueue轮转队列。筛选资源、候选直线检测、A*扩展和路径回溯均可暂停，逐帧接续，不重新丢弃已完成搜索。
- 世界每帧最多推进2048小步，同时以2ms为软预算；每个小步完成后检查时钟，单次碰撞函数或排序无法中途抢占，因此不是严格的2ms墙钟上限。
- A*单次仍限制900节点，直线失败后只在接近目标时检查最终连线。已找到直达目标不再重复检查完整直线。日常行走只复查即将走过的一小段，门关闭或障碍变化后仍会停下重新寻路。
- 搜索完成无目标时至少间隔一秒重试；搜索期间等待结果。牵引仍响应玩家移动，起点明显变化、权限变化、解除驯养、死亡或移除时取消不适用的任务；任务不写存档。
- canStand已包含地形与静态阻挡校验，移除觅食回调里重复的isBlocked调用。
- 单机/房主执行搜索和食物消费，客人继续接收既有姿态、库存和进食表现；不新增动作、快照字段或SAVE_VERSION。
- 图鉴与玩法指南明确15米食物搜索及30米活动范围的区别。
- 临时采集进一步拆分动物补刷准备、追击准备、移动战斗与动画、觅食移动与驯养、觅食搜索队列和繁殖，便于真机确认实际耗时归属。

## 验证与结论边界

- `node scripts/test-foraging-queue.mts`：12只动物、80个不可达自然食物点，验证全世界每帧碰撞检查不超过2048、轮转公平、2ms软预算、任务取消、近段碰撞检查、门关闭、过期食物不重复消费，以及14.99/15/15.01/17/30/60米目标边界。当前压力用例在157帧内分批完成，最大2048次碰撞采样/帧。
- 在缩小半径前的56米压力场景中，fb90a67的同步选择一次更新累计430704次碰撞检查，证明只限制A*终点连线仍不能约束整轮觅食工作量。此数字是人工压力用例，不是玩家报告里的实际调用次数。
- `test-food-path-budget.mts`验证底层A*可达绕路、封闭围栏及长线检测预算；底层通用算法测试可使用大于实际觅食半径的输入。
- `test-husbandry-care.mts`在15米范围内布局食物，运行六小时饲养数值模拟；`test-husbandry.mts`验证首次驯养、储粮阈值、争食、产物与客人快照；`test-lasso.mts`验证套索及绳长。测试使用加速推进搜索的场景只验证玩法结算，单帧预算由独立队列压力测试覆盖。
- 第173天云存档的静止两分钟Node部分逻辑复算未出现增长，与此次第80天真机报告不是同一场景。Node测试不包含真机WebGL、React和玩家实际操作，仍需通过同一设备、同一场景重新采集验证，不能以构建成功宣称所有卡顿已消除。
