# 联机连接方式与服务器中转

## 背景

现有 WebRTC 直连在部分网络下难以建立连接，需要通过当前自有服务器转发游戏数据。房主仍是开房玩家，所有玩法、动作结算、快照生成和存档留在房主端。

## 需求描述

- 提供好友直连（默认）、服务器中转、局域网（置灰，暂未开放）三个选择。
- 服务器默认同时最多 2 个房间，每房最多 4 人，包含房主；人数、房间数可通过服务器配置调整。
- 服务器房间名额满只禁止新建；已有未满员房间仍可加入。房间满员禁止新增连接，既有玩家不被踢出、不自动切换连接方式。
- 新服务独立放在与 `server/` 同级的 `relay/`，沿用现有部署与 HTTPS 入口。

## 设计方案

### 手机界面与邀请

创建/加入页顶部使用纵向三张选择卡，奶油底、蓝色选中边框；卡片最小高度 62px，刷新/取消等触控区至少 44px。创建/连接期间禁止切换；客人可主动取消后更换方式。创建成功只显示已选方式和邀请，不支持房内热切换。

选择中转时每 15 秒读取一次 `GET /relay/status`，单次最多等待 6 秒，显示“中转房间 X / Y · 每房最多 Z 人，含房主”。开房满额时禁用创建并提供刷新，加入页不因全局房间满而禁用。状态查询失败提供重试/直连提示；服务端最终裁定每次创建和加入。等待大厅与游戏内设置显示人数/上限和连接方式。

单机设置复用同一个组件。游戏中途开房不换岛屿；中转房主失联显示通知并清除无效房间码，可在设置重新开房，继续当前岛屿并分享新码。房主离线时不会将岛屿托管给服务器。

中转邀请使用 `?room=xxxxx&connection=relay`；旧邀请/缺少参数仍为直连。扫码自动选择，手输代码提示选择同一种方式。最近房间记录新增可选 `mode`，旧记录默认为 `direct`，断线重进使用上次连接方式，不受先前邀请覆盖。

### 传输与权威边界

`GameConnection` 统一 `connected/send/close` 和回调；保留 `PeerNet`，新增 `RelayRoom` + `RelayPeer`。房主一条 WebSocket 持有多条虚拟客人链路；客人一条 WebSocket 只连接房主。`NetHost` 仍创建玩家会话，`Actions.ts` 仍权威校验动作；`NetGuest` 沿用预测、快照应用、事件补播和角色恢复。

服务器只解析中转外层的 `create/join/data/drop/ping`，游戏 JSON 作为不透明字符串转发。客人发送方由 socket 绑定，客人不能直发其他客人；房主只能向本房间已有 peer 定向发送。所有消息可靠、有序转发，不能随意丢弃依赖前序基线的玩家/动物/世界增量。大欢迎包无需 WebRTC 的单帧分片，但受 8 MiB 包含路由封装的消息限制；客户端与服务端发送缓冲上限 16 MiB，超限关闭连接并提示重连或使用直连，防止无限积压。房主共用连接积压时整房断开。

`RelayPeer` 每秒测量经中转到对端的 RTT，流量浮层统计游戏载荷；不把中转服务器的 ping 当作房主延迟。游戏协议和 `SAVE_VERSION` 不变，不改持久化物品 ID。玩法指南新增“与朋友联机”，小红书构建不展示。

### 容量与连接生命周期

服务器在单进程同步检查并占位，连接成功登记就计入人数（包括尚未发送游戏 hello 的连接），避免并发超额。默认 `RELAY_MAX_ROOMS=2`、`RELAY_MAX_PLAYERS=4`；允许房间数 1～100、人数 2～32，超出范围启动失败。房间码独立于直连信令，因此同码必须搭配连接方式使用。

客户端 10 秒连接超时，每 5 秒发应用层心跳，服务端超过 20 秒没有客户端消息回收；未登记连接最多 10 秒。状态查询不占 WebSocket 或房间名额。客人离线释放在线名额；房主离线删除房间并关闭客人连接。客户端关闭、失败重试和取消均释放 socket、回调、心跳和 RTT。

客人恢复记录沿用原房主内存中的 5 分钟令牌，不占在线席位；重连仍需该房间存在且未满员。中转服务重启不恢复房间或托管游戏，房主本机岛屿不丢失。

### 部署与验证

独立容器仅暴露 Docker 私网 3002，限额 256 MiB / 0.5 CPU，由现有 Nginx 443 代理 `/relay` 和 `/relay/status`。Compose 可通过宿主环境中的 `RELAY_MAX_ROOMS/RELAY_MAX_PLAYERS` 调整，客户端显示服务端返回值，不硬编码上限。

Actions 上传 `relay/` 源码和独立 lockfile，排除开发 `node_modules`；构建 API 与 relay 镜像。部署验收增加状态 revision 与真实 WSS 心跳检查，不创建测试房间，失败按已有流程回滚。首次尚未部署该服务时，本地 H5 会如实显示中转服务不可用；界面和好友直连可本地验证，中转端到端由自动化临时服务验证，公网手机互联待服务部署后验证。

`node scripts/test-relay.mts` 覆盖并发第三房拒绝、含房主的四人容量、可配置容量、定向路由及跨房间隔离、大消息与连续增量顺序、主动/异常离线名额回收、注册/心跳超时、坏包与过大消息、真实客户端房主权威动作、欢迎开局、令牌重连、取消重试和邀请模式。`node scripts/test-multiplayer-connection.mts` 回归现有直连握手和信令。按仓库要求继续类型检查、H5 构建、ZIP 校验解压与本地提交；手机运行时验证由用户完成。
