# 联机连接方式与服务器中转

## 背景

现有 WebRTC 直连在部分网络下难以建立连接，需要通过当前自有服务器转发游戏数据。房主仍是开房玩家，所有玩法、动作结算、快照生成和存档留在房主端。

## 需求描述

- 提供好友直连（默认）和服务器中转两个选择。
- 进入创建房间/游戏内多人入口时先读取一次中转名额，未选中也提前知道是否满员；满员时中转卡片显示已满，不阻塞加入已有房间。
- 服务器默认同时最多 150 个房间，每房最多 4 人，包含房主；人数、房间数可通过服务器配置调整。
- 服务器房间名额满只禁止新建；已有未满员房间仍可加入。房间满员禁止新增连接，既有玩家不被踢出、不自动切换连接方式。
- 服务独立放在与 `server/` 同级的 `relay/`，生产入口为 `wss://193.112.25.170/relay`，使用独立服务器与可信 HTTPS IP 证书。

## 设计方案

### 手机界面与邀请

创建页顶部好友直连（左）与服务器中转（右）并排两张选择卡，奶油底、蓝色选中边框；卡片为方式名称、右侧徽标（默认/免费限量/已选）的单行紧凑布局，最小高度 48px，刷新/取消等触控区至少 44px。选中方式下方固定展示对应提示：好友直连提示双方网络需要可互通，连接失败说明双方当前网络暂不支持好友直连；中转提示仅少量免费房间、满员需排队，并提示可能比较卡、可以尝试好友直连。开房端（创建房间与游戏内设置）进入页面即读取一次中转名额，未选中中转也提前获知容量：满员且未选中时中转卡片徽标由「免费限量」变为暖色「已满」。创建期间禁止切换；加入页仅输入房间码，按位数自动识别方式，不展示位数说明与已识别方式提示，不查询全局开房名额，客人可主动取消后重新输入。创建成功只显示已选方式和邀请，不支持房内热切换。

选择中转时每 15 秒读取一次 `GET /relay/status`，单次最多等待 6 秒；直连态只在进入页面时读取一次，不轮询。显示“中转房间 X / Y · 每房最多 Z 人，含房主”。开房满额时禁用创建并提供刷新，加入页不因全局房间满而禁用。状态查询失败提供重试/直连提示；服务端最终裁定每次创建和加入。等待大厅与游戏内设置显示人数/上限和连接方式。

单机设置默认只显示「开启多人模式」按钮，点击后进入独立弹窗，复用同一个连接方式组件与网页版引导；点击「确认创建房间」才发起开房。创建期间禁止重复确认和返回，失败留在弹窗提示并允许重试，成功返回设置显示房间码、二维码与分享。关闭弹窗不创建房间、不消耗名额。小红书构建不显示入口与弹窗。游戏中途开房不换岛屿；中转房主失联显示通知并清除无效房间码，可在设置重新开房，继续当前岛屿并分享新码。房主离线时不会将岛屿托管给服务器。

房间码统一按位数路由：6 位为好友直连，5 位为服务器中转。加入页、邀请链接、二维码和断线重连均按此规则识别，不依赖 connection 参数；中转分享链接仍附带该参数供旧版中转客户端使用。旧版五位直连房间需更新后重新创建，最近房间记录中五位且非 relay 的记录不再用于自动重连。持久化存档版本不变。

### 传输与权威边界

`GameConnection` 统一 `connected/send/close` 和回调；保留 `PeerNet`，新增 `RelayRoom` + `RelayPeer`。房主一条 WebSocket 持有多条虚拟客人链路；客人一条 WebSocket 只连接房主。`NetHost` 仍创建玩家会话，`Actions.ts` 仍权威校验动作；`NetGuest` 沿用预测、快照应用、事件补播和角色恢复。

服务器只解析中转外层的 `create/join/data/drop/ping`，游戏 JSON 作为不透明字符串转发。客人发送方由 socket 绑定，客人不能直发其他客人；房主只能向本房间已有 peer 定向发送。所有消息可靠、有序转发，不能随意丢弃依赖前序基线的玩家/动物/世界增量。大欢迎包无需 WebRTC 的单帧分片，但受 8 MiB 包含路由封装的消息限制；客户端与服务端发送缓冲上限 16 MiB，超限关闭连接并提示重连或使用直连，防止无限积压。房主共用连接积压时整房断开。

`RelayPeer` 每秒测量经中转到对端的 RTT，流量浮层统计游戏载荷；不把中转服务器的 ping 当作房主延迟。游戏协议和 `SAVE_VERSION` 不变，不改持久化物品 ID。玩法指南新增“与朋友联机”，小红书构建不展示。

### 容量与连接生命周期

服务器在单进程同步检查并占位，连接成功登记就计入人数（包括尚未发送游戏 hello 的连接），避免并发超额。默认 `RELAY_MAX_ROOMS=150`、`RELAY_MAX_PLAYERS=4`；允许房间数 1～150、人数 2～32，超出范围启动失败。中转五位码与直连六位码按位数区分，加入时无需选择连接方式。

客户端 10 秒连接超时，每 5 秒发应用层心跳，客户端与服务端均在超过 45 秒没有对端消息时回收；未登记连接最多 10 秒。状态查询不占 WebSocket 或房间名额。客人离线释放在线名额；房主离线删除房间并关闭客人连接。客户端关闭、失败重试和取消均释放 socket、回调、心跳和 RTT。

客人恢复记录沿用原房主内存中的 5 分钟令牌，不占在线席位；重连仍需该房间存在且未满员。中转服务重启不恢复房间或托管游戏，房主本机岛屿不丢失。

### 部署与验证

独立服务器 `193.112.25.170` 使用 `relay/deployment/compose.yml`，容器仅暴露 Docker 私网 3002，限额 256 MiB / 0.5 CPU，由该服务器 Nginx 443 代理 `/relay` 和 `/relay/status`。Compose 可通过宿主环境中的 `RELAY_MAX_ROOMS/RELAY_MAX_PLAYERS` 调整，客户端显示服务端返回值，不硬编码上限。证书自动续期与手动发布验收见 [独立中转运维](../relay/deployment/README.md)。主站、云存档 API 和直连信令地址保持原配置；图鉴不展示基础设施 IP，玩法机制没有变化，无需修改条目。

原主站 Actions 继续上传 `relay/` 源码和独立 lockfile、构建旧入口 relay 镜像并验收其版本，用于兼容旧客户端；独立服务器另行发布，验收新 IP 的状态 revision 与真实 WSS 心跳，不创建测试房间。旧、新入口房间不互通，双方需更新至同版客户端。公网手机互联由用户验证。

`node scripts/test-relay.mts` 覆盖并发第三房拒绝、含房主的四人容量、可配置容量、定向路由及跨房间隔离、大消息与连续增量顺序、主动/异常离线名额回收、注册/心跳超时、坏包与过大消息、真实客户端房主权威动作、欢迎开局、令牌重连、取消重试和邀请模式。`node scripts/test-multiplayer-connection.mts` 回归现有直连握手和信令。按仓库要求继续类型检查、H5 构建、ZIP 校验解压与本地提交；手机运行时验证由用户完成。

创建大厅或游戏内开房弹窗的连接方式组件打开时，即在客户端检测好友直连接口支持情况；接口缺失时，直连卡片标记「需网页版」，选中直连立即显示网页版复制引导，无需先点击创建。不隐藏或禁用连接选项，不自动切换中转；接口存在仅说明具备直连能力，不保证网络握手成功。实际创建/加入时仍保留底层检查。

网页版引导使用统一雾海蓝按钮卡片，只说明复制后在手机系统浏览器打开，不推荐服务器中转。默认不展示原始网址；复制成功仅显示简短反馈，复制失败才展示可选中的只读文本供手动复制。按钮触控区至少 44px，弹窗内容在小屏内滚动，底部确认与返回固定可见。
