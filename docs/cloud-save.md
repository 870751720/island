# 存档码与手动云存档

## 背景

H5 容器可能丢失本地数据。普通网页和 H5 统一使用自有服务器备份，删除 TapTap 专用 SDK 调用与渠道判断；小红书不提供云存档入口。本地自动存档逻辑保持不变；非小红书的入场流程增加首次存档码引导。

## 需求描述

- 主菜单「云存档」首次打开要求输入 1～20 位存档码，区分大小写，去除首尾空白，不允许内部空白和控制字符。提示一定要牢记：H5 数据可能丢失，凭码找回；同一码可以读取和覆盖同一份存档，不提供账号、密码重置或多个槽位。
- 非小红书用户开始/继续游戏、创建/加入房间（含邀请链接）时，若本地没有有效存档码，必须先看到存档码引导。可跳过，但需再次确认“H5 本地数据容易丢失，清理数据或换设备后可能永久丢失，无法找回”。跳过不记住跳过状态，下次入场仍提示；已有有效存档码不重复要求输入，也不自动上传。
- 输入后先检查云端，只把 404 当作无云档；网络或数据校验失败保持在输入界面，禁止当作空档上传。有云档时显示云端保存时间和天数、本地天数，让用户明确选择：使用云端则完整覆盖本地并重载主界面，取消原先的开新档/入房动作，绝不上传；使用本地则记住码，入场后上传一次并覆盖该码的云档。若单机已有本地岛屿，选择本地会继续该岛，而不是执行先前待处理的开新档。
- 没有云档时用户点击“同意并开始”，进入游戏并在世界初始化完成后上传一次；新岛备份包含初始世界，既有本地自动保存时机不变。之后仍需手动上传。上传失败明确提示并提供重试/稍后手动上传，不伪报成功；重试使用同一份首次快照，重新入场不重复自动上传。
- 存档码保存在 `island.cloud.code.v1`，下次不重复输入；弹窗展示当前码并允许更换。更换码不迁移或删除原云档。
- 上传读取已经保存的全部游戏 localStorage，确认后替换该码唯一云档；除首次入场明确同意的一次上传外，不自动上传或下载，不进行多设备冲突判断，以服务端最后完成的写入为准。
- 下载展示时间与生存天数，确认后完整替换本机游戏持久化数据，包含世界、角色、传承、配方收藏、偏好、教学状态、联机记录和存档码。删除备份中不存在的游戏键；非游戏同源数据不受影响。
- 没有进行中的岛屿也允许备份其余数据；恢复这种备份会清除本机岛屿。死亡后允许覆盖上传或读取之前的云档。
- 成功恢复后重载页面，避免已有内存缓存覆盖导入数据；读取、格式校验或下载失败时不写本地；本地覆盖失败时尝试回滚，并如实报告回滚失败。
- 入口与操作均为触屏设计，按钮不小于 44px，小屏和横屏弹窗可滚动。手动上传下载在主菜单操作；首次同意的上传在入场后执行，联机房主退出后房间仍按原规则解散。

## 设计方案

### 客户端

`src/game/cloud/` 分离存档码、HTTP 接口、快照校验与本地恢复；`src/ui/cloud/` 管理手动弹窗、入场引导 `CloudStartGate` 和一次性上传状态 `InitialCloudBackup`。`GameCanvas` 在清档和创建房间之前拦截入场；`StartCloudSave` 负责云档查询/恢复与首次快照，使用新世界的 `collectSave()` 仅替换上传包中的世界，不提前写入 localStorage。上传请求在组件中锁定，重渲染不会重复发送。`shared/cloudSave.ts` 提供服务端与客户端共享的码和传输格式校验。

备份格式 `island-cloud-backup` v1，包含时间戳与所有 `island.` / `island-` 前缀的键值，未来新增游戏键自动纳入。存档传输上限 10 MiB、256 个键。游戏内部 `SAVE_VERSION` 保持 32，兼容策略不变；不兼容云档在本地覆盖前拒绝。旧 TapTap 备份不接入。

API 默认 `https://43.110.116.98/api/save`，可通过构建变量 `NEXT_PUBLIC_CLOUD_API_URL` 指定来源。码通过 Authorization 请求头编码传输，不进入 URL、浏览器历史或访问日志。请求超时 30 秒，不自动重试写入；超时表示结果不确定，用户可重新读取确认。

### 服务端

独立 `server/` 目录，Node 22.18+ 原生 HTTP 与 SQLite，无游戏模拟。每个存档码经服务端 HMAC 映射到一条记录，SQLite 单语句原子覆盖、WAL 与 FULL 同步提供持久化。完整备份内容包含用户输入的存档码，因此数据库、密钥和备份都属于私密数据。

- `GET /api/health`：健康状态和发布 SHA。
- `GET /api/save`：获取当前码的存档，不存在返回 404。
- `PUT /api/save`：校验格式、大小和备份内存档码后覆盖；无历史槽位。
- 认证头为 `SaveCode <URI 编码的码>`，服务端验证长度，单 IP 每分钟最多 30 次存档请求；nginx 覆盖真实 IP 头，API 不发布宿主机端口。
- CORS 支持任意来源且不使用 Cookie，兼容 H5 容器和本地文件；所有读写仍要求显式存档码。码就是完整访问凭据，短码和重复码不具备账号隔离能力，首屏必须提醒用户使用难猜组合。

`server/compose.yml` 管理 API、HTTPS 反向代理和 IP 证书续期。SQLite 与服务端密钥位于 `/opt/island/shared/`，不进入发布包；更新和回滚只替换代码。数据库运维备份需使用 SQLite 在线备份或停服后一并保留 WAL，不能只复制运行中的主数据库文件。

## 验证

`node scripts/test-cloud-save.mts` 验证全量恢复与删除、失败回滚、损坏备份拒绝、码长度、API 隔离和覆盖、CORS、限流、体积限制及数据库重启持久化；同时验证空云档与网络故障的区分、选择云档不上传、首次新世界快照不改变本地自动保存、客人不上传远端世界、本地码被删除后重新提示。游戏运行时与手机实际交互由用户本地验证。
