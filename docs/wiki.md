# 游戏图鉴（Wiki）

## 背景

游戏内道具数量多（材料、工具、装备、食物、设施等 180 余件），玩家此前只能通过背包逐件点开查看描述，缺少一个集中翻阅、了解每件物品用途与属性的入口。希望有一个类似 wiki 的图鉴页面，从游戏设置进入，按分类浏览物品介绍。

## 需求描述

- 设置面板新增「游戏图鉴」入口，点击后弹出图鉴页面；关闭图鉴回到设置，交互路径为 设置 → 图鉴 → 详情。
- 图鉴一级分类为「物品」与「生物」；物品覆盖游戏内全部物品，每件物品有介绍。
- 物品详情展示获得方式：有配方的道具展示配方（材料、数量、制作设施），设施与材料芯片均为可点击的「图标 + 名称」组合，跳转到对应道具详情，可层层深入并逐层返回；需要等级的配方以对应等级工作台的芯片表达等级要求。
- 物品详情带来源标签与「获得方式」区块：来源覆盖合成、采集、击杀、钓鱼、种植、加工、畜牧、伙伴觅食、赠礼等途径。
- 交互友好（手机触屏优先）：大触控区、搜索、连续翻阅；界面样式与游戏内奶油鼠尾草主题保持一致。
- 生物平铺展示，不设二级分类，通过卡片标签区分习性与互动能力。收录兔子、绵羊、野牛、狼、熊、鳄鱼、薯条、可乐、鸟、螃蟹、海中巨影共 11 种；不收录蝴蝶和可钓获鱼虾等水产。

## 设计方案

### 入口与层级（`src/ui/`）

- `SettingsPanel.tsx`：「游戏」页顶部新增「📖 游戏图鉴」按钮（`MenuIcon book` 图标），点击回调 `onOpenWiki`。
- `GameplayUI.tsx`：新增 `wikiOpen` 状态，渲染 `WikiPanel`；图鉴遮罩 `z-index: 210` 叠在设置（200）之上，关闭后设置仍在，回到入口位置。

### 图鉴模块（`src/ui/wiki/`）

- `WikiPanel.tsx`：图鉴弹层骨架（遮罩 + 面板 + 关闭按钮），顶层分类导航由 `WIKI_CATEGORIES` 登记表驱动，登记「物品」和「生物」。内容进入详情阅读时收起顶层分类导航、返回浏览视图恢复（内容组件经 `onDetailChange` 上报）。
- `ItemsWiki.tsx`：「物品」分类内容，浏览与详情两级视图：
  - 浏览视图：搜索框 + 物品分类 tab（材料/工具/装备/食物/设施/道具，复用 `ITEM_CATEGORIES`）+ 物品网格（图标 + 名称的方块入口；工具显示代表整个等级族的统一名「斧/镐/铲/锄/鱼竿/弓/剑/剪刀」，不偏指一级的「木斧」等）；
  - 搜索时跨全部分类匹配名称，结果按分类分组展示，空结果显示友好提示；工具同时匹配统一名与各等级名（搜「斧」「铁斧」都能命中）；
  - 详情视图：大图标、名称、标签行（分类 + 来源分组标签）、物品描述（`ITEMS.description`）、属性行、「获得方式」区块（每条途径单行排列：设施芯片 + 材料芯片（带数量）+ 动作文字或途径主体芯片，一行读完「用什么设施、用什么材料做什么」；芯片可点击跳转对应图鉴详情，等级要求用对应等级工作台的芯片表达；种植途径以「种子图标 + 种子名」的可点击芯片替代「种植X」文字），底部「上一件 / 下一件」在当前列表内循环翻阅，「‹ 返回」逐层退回浏览轨迹。
- `itemSources.ts`：获得途径的数据推导模块。正向索引（kind → 获得方式）在模块加载时从各系统既有数据表推导，不保留手抄镜像表：
  - 合成：`Crafting.ts` `RECIPES`（材料/站点/工作台等级/产物数，工具多级配方以配方名区分）、`WORKBENCH_UPGRADE_COST`（工作台升级）；
  - 采集：`HarvestTable.ts` `HARVEST_CONFIG`（各资源点的产出声明表，结算与图鉴共用同一张表）与 `DIG_YIELD`（铲子整棵挖走），树种种子/果实经 `expandHarvestDrop` 展开，概率产出直接显示具体百分比；
  - 击杀：`Wildlife.ts` `SPECIES` 战利品 + `RARE_LOOT` 稀有掉落表（冒险家的经验书、作物种子，结算 `lootOf` 与图鉴共用）+ 弓箭射鸟；
  - 钓鱼：`FishTable.ts` `JUNK_LOOT`/`SEA_FISH`/`POND_FISH`/`TREASURE_LOOT`（珍宝池同时来自局外「碎石成金」挖陨石）；
  - 种植：`Crop.ts` `CROP_SPECS`（收获产物与返还种子；产物途径经 `target` 指向种子，渲染为种子芯片替代「种植X」文字，种子自身的返还途径保留文字）；
  - 加工：`Food.ts` `COOKABLE`/`BOILABLE`、`Wine.ts` `BREWABLE` 与 `BREW_COST`、`BAIT_YIELD`（饵料桶）、`Smelter.ts` 冶炼、`LoomSystem.ts` 纺织、火堆燃尽遗留熄灭的火堆；
  - 畜牧 / 伙伴 / 赠礼：`AnimalHusbandry.ts` `LIVESTOCK_PRODUCE`（物种 → 奶/毛产出表，定时产出结算、生物图鉴与物品来源共用）、`CompanionDefinition.ts` `CAT_FINDS`、`PoseidonGrace.ts` `POSEIDON_GIFT_KINDS`（皮套系列属死亡补偿，经 `GIFT_WIKI_HIDDEN` 排除，不在图鉴列为获得途径，仅「海神的信」保留）。
- 详情跳转采用浏览轨迹栈（`trail`）：从网格或搜索进入压入首层，点击配方材料时在目标所属分类的完整列表中打开（便于上一件/下一件连续翻阅），返回按钮逐层退回，退空回到浏览视图。
- `itemWiki.ts`：图鉴数据准备。以 `ITEMS` 为基础（名称、图标、描述），按 `itemCategory` 分组、`itemSortIndex` 排序（与背包整理同序），并从既有系统汇总属性行：
  - `Food.ts` `FOODS` → 饱食/水分/生命回复；
  - `ItemDef.burnTime` → 投入火堆的燃烧时长；
  - `Crafting.ts` `toolName` → 工具等级名（木斧 → 石斧 → 铁斧；无升级的工具如剪刀显示「无」），`TOOL_FAMILY_NAMES` → 工具统一名（详情标题与网格入口用）；
  - `Equipment.ts` `EQUIPMENT` → 背包容量、防御、减伤、口渴速度。
- `WikiPanel.module.css`：样式沿用设置面板的视觉语言（同尺寸公式、圆角、边框、渐变底、44px 触控区），含横屏容器查询的紧凑适配；内容区为「筛选区固定 + 列表滚动」结构。

### 生物分类

- `CreaturesWiki.tsx`：搜索框下直接展示三列生物卡片，不设子分类、分组标题或标签筛选栏。每张卡片显示静态图标、名称与两个特性标签；搜索匹配名称或标签，输入完整标签时优先精确匹配，避免「可驯养」误命中「不可驯养」，空结果给出提示。
- 生物详情首排左侧为头像和名称，基础属性利用名称右侧空位就地展示，标签位于名称下方；随后展示简介、出没地点、习性与应对、互动方式、驯养产出或伙伴觅食、击杀掉落、可投喂食物。没有数据的区块不展示。战斗数值为基础配置，掉落标明成年基础产出，概率掉落单独注记。
- 生物基础属性与名称共用第一排，不单独增加属性行、底色卡片或标题。48px 头像旁的内容区中，16px 名称左对齐，属性靠右，用 10px 短标签「生命 / 攻击 / 驯养」、14px 加粗等宽数值和细分隔线紧凑横排，并保留完整辅助名称。野牛的护幼和激怒反击在习性中说明，属性区只放数值；无属性的生物不留空白。样式限定生物详情，不影响物品属性布局。
- `creatureWiki.ts`：单一生物登记表与玩法介绍；物种名称和基础数值读取 `Wildlife`，套索能力读取 `LassoRules`，食谱按 `FOODS.eaters` 与饱食值推导，爱心与生产时间读取 `AnimalHusbandry`，驯养产出读取 `LIVESTOCK_PRODUCE`（与玩法结算共用），伙伴名称与觅食产物读取 `CompanionDefinition`。额外掉落读取 `Wildlife.RARE_LOOT`（与 `lootOf` 结算共用，备注经 `rareLootNote` 从概率数字推导），不另抄一套概率表；基础习性与场景生物介绍按对应玩法维护。
- `CreatureIcon.tsx`：复用现有 SVG 笔触绘制动物图标，薯条、可乐复用伙伴头像；不引入贴图、外部模型或额外 WebGL 上下文。
- 兔子头像使用完整露出的修长双耳、浅色圆脸与小鼻口；绵羊头像使用奶油色卷毛轮廓、侧耳和深色窄脸，保持小尺寸下的物种辨识度。
- `WikiText.tsx`：生物正文支持显式物品引用，原位显示「18px 物品图标＋文字」按钮，触控区至少 44px，图标与文字整体点击，使用滚动容差手势；点击进入对应物品详情，逐层返回后恢复生物详情的滚动位置。文案与持久化物品 ID 分开，不按名称自动识别链接。
- 引用覆盖生物简介、出没地点、习性、互动与生产说明：兔子的铲子，动物互动中的套索，羊的羊奶、羊毛与剪刀，野牛的牛奶，伙伴的食料桶、宠物窝，鸟的弓箭与鸟肉，螃蟹的蟹肉。不可使用套索的说明保留否定上下文，跳转只供查阅，不代表可使用。泛称食物、武器、护甲，以及没有物品条目的兔子洞、地形和行为词保留普通文字。范围仅为生物分类，物品分类正文不自动增加引用。
- `ItemChip.tsx`：物品与生物图鉴共用可点击物品芯片。生物详情点击食物或产物时，使用 `ItemsWiki` 的 `initialKind/onExit` 进入既有物品详情，材料跳转仍按原轨迹逐层返回，最外层返回生物详情并恢复滚动位置。
- 生物相关产物的补充标注放进对应物品按钮内右下角：兔子卷心菜种子 10%、野牛玉米种子 3%、狼经验书 30%、熊草莓种子 50%，以及熊经验书「必掉 ×3」和可乐觅食产物的阶段说明。图标与名称维持普通按钮的垂直居中位置、间距与内边距；标注使用 9px 小字、10px 行高，绝对定位于右侧 6px、底部 2px 的空位，不参与布局、不把名称顶高或额外撑高按钮，横屏紧凑按钮同样适用。标注区域也属于同一点击目标；物品分类不添加新标注。
- 上一种/下一种仅在进入详情时的搜索结果中循环，只有一项时禁用翻页；返回列表保留搜索和滚动位置。详情阅读期间继续隐藏顶层分类导航。固定按钮沿用 `pressAction`，网格和物品芯片沿用滚动容差手势。
- 全部条目直接开放，不增加发现进度或解锁条件；房主与客人本地查阅相同静态资料，无动作上行、权威状态修改、快照或事件补播，协议与存档版本均不变。

### 触控可靠性（沿用 HUD 既有规则）

- HUD 快照约每 250ms 触发整棵玩法 UI 重渲染，`click` 结算易在按下与抬起之间丢目标（历史上状态图标、手持选择面板均按此定位修复）。图鉴按同一套规则处理，触屏不再出现「要点多次才生效」：
  - 固定区控件（图鉴分类导航、关闭、物品子分类 tab、返回列表、上一件/下一件）用 `pressAction` 按下即执行，尾随 `click` 不重复触发，键盘/辅助技术激活保留；
  - 打开图鉴（设置内入口）、关闭图鉴（遮罩与关闭按钮）、返回列表都会让手指下方换成另一块 UI，配 `swallowTrailingClick()` 在 `document` 捕获阶段吞掉本次手势的尾随 `click`，下一次按下开始新手势即解除，800ms 兜底超时；
  - 滚动网格内的物品格不能用按下即执行（轻扫滚动会误开详情），改用 `useScrollAreaTap` 在同一按钮上配对按下/抬起，位移 ≤12px 才打开详情，滚动或触点取消不触发；
  - 格子、tab 等按钮的内部节点 `pointer-events: none`，指针命中固定落在稳定按钮节点上，重渲染不替换事件目标。
  - 以上手势集中在 `src/ui/wiki/wikiTaps.ts`，仅图鉴模块使用，不影响其他 UI。

### 联机与存档

- 图鉴为纯静态本地展示 UI，不产生动作与状态变化，无新增网络同步或存档字段，`SAVE_VERSION` 不变；房主与客人各自本地打开，互不影响。
