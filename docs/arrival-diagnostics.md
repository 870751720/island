# 登岛诊断日志

## 背景
玩家停留在“正在登上小岛”时，需要提供启动现场以定位设备兼容或初始化异常。

## 需求描述
加载页始终提供至少 44px 高的“复制诊断日志”按钮。等待超过 15 秒显示等待时间；发生异常时提示反馈。剪贴板不可用或拒绝授权时，显示可长按全选复制的只读文本。

## 设计方案
- 从游戏生命周期 effect 开始采集，记录双帧等待、游戏实例构建、世界状态读取、WebGL 创建、地形与资源生成、玩家和系统创建、存档恢复、游戏循环启动及首帧完成，带相对耗时。
- 捕获同步初始化异常、登岛期间未处理的全局异常、Promise 拒绝和 WebGL 上下文丢失。失败保留加载页与复制入口；成功首帧后停止采集，卸载移除监听。
- 报告包含诊断格式版本、启动时间、浏览器 UA、视口、像素比、网络在线状态、页面可见性、安全上下文、协议、单机/房主/客人模式、是否有初始存档及错误堆栈。
- 日志仅存于内存，最多 100 条、单次异常最多 6000 字符。不导出存档正文、玩家名字、房间码或联机凭证，不上传日志；清除堆栈 URL 查询参数与片段，并遮蔽常见凭证字段。
- 单机、房主、客人各自记录本地初始化，不更改权威结算、动作上行、快照同步或存档版本。
- 按钮每次点击重新生成现场文本。诊断针对加载页已出现的阶段，无法在主线程持续阻塞、浏览器进程崩溃或页面脚本尚未执行时响应点击。
