# 多人联机(WebRTC 房主权威)

## 背景

游戏目前是纯单机:一个 `Game` 实例绑定唯一 `Player`,玩法判定、存档、HUD 全部围绕单玩家。目标是支持多人联机共玩同一座岛(人数不设上限),且不引入任何游戏服务器、保持 GitHub Pages 纯静态部署。

## 需求描述

- 多人(2 人即可开玩,人数不设上限)在同一个房主权威世界中共同生存；岛形由地形种子生成，自然资源由房主持有并同步完整状态。
- 传输:WebRTC DataChannel 玩家直连(房主星形拓扑),第三方服务不承载游戏数据。
- 信令:五位数字房间码或二维码,通过国内公共 MQTT 自动交换 WebRTC 握手信息。
- 权威模型:房主客户端跑完整玩法模拟;客人只跑表现层 + 自身移动预测。
- 存档:联机时房主持档;单机模式保持现状;存档结构变化时 SAVE_VERSION +1。
- 断线:房主退出即全房解散;客人断线由房主按超时移除该会话。

## 设计方案

`Game` 的设施与玩家命令已分别由 `FacilityInteractionController` 和 `PlayerCommandController` 协调。客人端继续使用原有 action 名与参数上行，房主仍通过 `Actions.ts` 调用 `Game` 的稳定公开门面完成权威结算，状态由原有 HUD/世界快照回流；本次模块拆分不新增网络消息或持久化字段。

世界离散状态由 `WorldReplicationController` 维护客人镜像和 revision；增量断档时仍使用原有 world resync 请求全量快照。`PlayerSnapshotBuilder` 保持房主姿态载荷字段，`GuestHudSynchronizer` 负责将定向 HUD 回流到客人本地状态并补播纯表现效果。三者都不改变房主权威边界或网络协议。

### 连接状态与网络限制

- 握手阶段由 `PeerNet` 独立计时 30 秒，不应用房主的 10 秒心跳超时；两条数据通道打开时重置活跃时间，再检查心跳。客人从通道打开起每秒发送心跳，等待开局期间也保持连接；只有游戏就绪后才上行移动输入。
- 房主收到协议匹配的 `hello` 才将客人列入名单、创建游戏会话并通知加入，重复 `hello` 不重复接入。未加入的连接失败显示“连接未完成”，只有已加入的客人断线才显示离开，避免把信令握手失败误报为玩家离场。

- 房间信令回复只代表找到房间，客人此时显示“正在连接房主”；只有两条 WebRTC 数据通道都打开后，才显示“等待房主开始游戏”。
- 房主和客人的握手连接均在 30 秒内未完成时回收。客人显示当前网络暂时无法连接、确认房主在线或切换网络的提示，并允许重新加入；失败和重试清理旧连接，迟到回调不影响新连接。
- 连接失败无法确定具体运营商或 NAT 类型，不将运营商故障作为确定诊断。当前仅提供 STUN 直连，受限网络仍可能无法加入；本提示不等于修复网络穿透。
- 后续可接入国内托管 TURN，或将游戏消息改由托管 WebSocket/MQTT 中继转发，无需玩家自行维护服务器。公共 MQTT 服务面向测试，不能默认当作稳定游戏中继；正式接入需确认国内节点、额度、消息频率、认证和延迟。房主仍负责权威结算，客人动作上行与快照、事件回流语义保持一致。
- 本次不改变网络消息格式与存档版本。

### 模块划分

- `src/game/net/`:消息协议(`Protocol`)、WebRTC 连接(`PeerNet`)、在线房间信令(`Signaling`)、房主与客人会话总管。
- `src/game/mp/`:每玩家会话(`PlayerSession`:player + survival + inventory + equipment + tools)、远程玩家驱动(`RemoteDriver`)、世界状态同步(`WorldSync`)。

### 资源模型生命周期与白屏排查

- 房主仍权威结算资源采集、生长、放置与移除，客人沿用世界增量和完整快照回流；不新增网络字段、不改变存档版本。
- 客人处理资源列表时保留未变化树木的网格。只有树种、生长外观或树桩外观发生变化时才替换网格，单纯的可见性、朝向和计时变化不重建模型。
- 替换树模型、移除资源和退出游戏时释放资源点独占的几何体与材质；同一资源内部共享的网格资源只释放一次，避免持续游玩时 GPU 资源累积。
- WebGL 上下文丢失时允许浏览器恢复，并在控制台记录客人模式、几何体/纹理数量、绘制调用与画布尺寸；恢复时重新同步画布尺寸并记录恢复事件。浏览器不保证一定恢复，不能将输入仍可上行视为本地渲染正常的证据。
- 资源同步重复建模且不释放旧网格是已确认的泄漏；具体设备的白屏仍需结合上下文事件或异常堆栈判断，不将所有白屏一概归因于内存压力。

### 权威与同步

- 阴影稳定化为本地渲染：房主和客人各自将观察中心对齐到光源空间纹素网格，共用过滤参数；太阳方向沿用昼夜同步，无新增动作、快照字段、补播事件或存档字段。详见 [阴影稳定性](shadows.md)。

- 云层为纯本地环境表现：房主与客人使用同一组程序化柔边云纹理，以六朵稀疏的半透明云团呈现，各自更新漂移和相机朝向，不投射硬边阴影，不参与权威结算，无需动作上行、快照同步或事件补播，也不写入存档。

- 房主侧为每名客人建一个 `PlayerSession`(复用本地 Player 物理与动画,输入由网络摇杆写入 `player.input.setJoystick`,保证与本地移动完全一致的判定)。
- 客人侧:收到地形种子后重建相同岛形，再按房主完整资源列表建立资源布局；远程玩家用 Player 的「遥控模式」(`setNetPose` 插值)表现；权威状态(资源点/掉落物/放置物/动物/昼夜/天气)由 `WorldSync` 增量应用。
- 消息:客人→房主 `input`(摇杆)与 `action`(按钮语义,即 Game 公共方法参数化);房主→客人 `welcome`(种子+初始状态)、`snapshot`(10–15Hz)、`event`(音效/特效/拾取/死亡)。
- 持续受伤表现(伤口贴片/濒死血滴)为纯本地表现:房主在权威生存结算循环、客人在快照应用处各自调用 `player.setHealth`,血量本就随快照回流,无需新增消息。
- 雨天「雨水恩泽」效果(口渴减慢/作物加速/火堆与烹饪台燃速/钓鱼档位偏移)不新增同步字段:雨量本身已随玩家快照回流,口渴与燃料走既有权威结算和数值对账,作物生长沿用秒数柔和对账,钓鱼档位只在房主结算端 roll。
- 雪天(2026-09-10):`players` 快照 `weather` 枚举扩展 `'snow'` 并新增连续值 `snow`(雪量),客人端 `WeatherSystem.netSync` 携带雪量本地插值表现;雪天为纯表现,不参与任何权威结算。`gmSetWeather` 动作的枚举校验同步支持 `'snow'`,不升协议版本。

### 里程碑

- M1 多玩家抽象:Player 遥控模式、PlayerSession、Game 会话化、动物按最近玩家结算(单机行为不变)。
- M2 状态收拢与实体 id:按会话结算的交互系统(采集/制作/火堆/木箱/钓鱼等)、掉落物与动物 id、SAVE_VERSION=26、权威随机收敛。
- M3 网络层:PeerNet/RoomCode/NetSession、房主权威模拟、客人 guest 模式。
- M4 联机 UI:房间创建/加入、lobby、断线处理。
- M5 打磨:名字标签、事件同步、死亡规则联机化。
# 地图表现

地图不新增网络协议。房主直接读取权威玩家会话和设施系统；客人读取已有玩家姿态快照与工作台、床、火堆世界增量在本机重建的状态。地图只做只读表现，不参与结算。

## 自言自语

自言自语为纯本地表现层,不上行不同步:每个客户端(含客人)各自用本地可见状态触发台词(生存数值由快照回流,设施 count、昼夜、天气强度、陨石、漂流瓶在客人端均有本地表现)。详见 `mumble-system.md`。

## 海水视觉

房主与客人使用相同地形种子在本机生成海水深度纹理，按各自镜头覆盖海面；波纹、浅滩光纹与沿岸白沫由本地时间驱动，相位可不同。这些效果只参与渲染，不改变水位或游泳判定，不新增动作上行、快照字段或事件补播。移动与生存消耗继续由房主权威结算，存档版本保持不变。

### 动物与螃蟹补充节奏(2026-09)

动物(兔/羊/野牛/狼/熊)、螃蟹、鸟的种群补充改为逐只冷却(120~900 秒按物种),仍只在房主端结算,新个体沿用既有姿态快照回流、客人按 id 补建,不新增协议字段。

### 纯装饰物两端本地生成(2026-09)

场景装饰物(花/蘑菇/贝壳/海星,`world/Decorations.ts`)不可交互,不做任何同步:两端各自用 welcome 消息里已有的 `terrainSeed` 确定性生成,画面天然一致。详见 `docs/decorations.md`。

### 蚯蚓窝资源点化(2026-09)

蚯蚓生物及 ambient 通道(`AmbientState.worms`)整体移除;蚯蚓窝作为普通 props 资源点,捉蚯蚓/铲子挖窝/放回由房主权威结算(走既有 CollectSystem 与 `useBush` 动作),状态经 props 快照/世界增量回流,无专属协议字段。

### 砍树自然补种(2026-09)

砍倒成树第一阶段后,房主端在 `Props.seedRegrowTree` 里选点补种同树种树苗(避开所有在场玩家 18 米防穿帮),经 props 既有 `add` 增量回流客人,无专属协议字段;选点与同步细节见 `docs/trees.md`。

### 果树摘果同步(2026-09)

果树挂果/摘果走既有采集链路:房主为每个会话权威运行 CollectSystem,空手摘果由 `Props.pickFruit` 结算,`fruited` 字段经 props `set` 增量回流客人;挂果再生计时只在房主端推进(`updateFruitRegrow`),到点发 `fruited: true` 增量,客人不模拟计时。无专属协议字段,旧档 `fruited` 缺省视为挂果。

## 迭代记录

### 设施产出粒子客人端补播(2026-09)

- 修缮范围:饵料桶(鱼饵)、酿酒桶(酒)、冶炼炉(铁锭)、纺织机(布料)、烹饪台(汤品)的产出粒子原本只在权威端(单机/房主)播放,联机时客人看不到;现统一改为各系统 `netApply` 检测快照回流产出数量增加时本地补播同款粒子(初次全量同步的新设施不播,避免入岛时刷屏)。
- 玩家个人动作类粒子(采集/挖掘/投料/收取/摆放等)仍由动作发起端本地播放,不在此列。

### 酿酒桶与酒 Buff 同步(2026-09)

- 新增世界段 `brewBarrels` 与动作 `useBrewBarrel/brewBarrelFeed[kind,count]/brewBarrelCollect/brewBarrelTakeRaw`:放置/投料/收取由客人上行、房主权威结算,桶内 `kind/rawLeft/bottles/tickLeft` 经世界增量回流;发酵计时(每 45 秒 2 原料→1 瓶)只在房主端推进,铲子挖走同饵料桶。
- 喝酒 Buff(舒爽/晕晕的):计时器在 `Player` 上,由房主权威端的进食完成回调施加(客人 `eatFood` 动作上行);姿态快照 `PlayerState` 新增 `refresh`/`tipsy` 剩余秒数字段,客人端对齐本地计时器(差值>1s 才改写),使移动加速/减速在客人本地预测移动中生效,HUD buff 列表随各端 HUD 快照展示。
- 剑增伤:客人 `swordHit` 上行后,房主按该客人会话(房主侧副本)的晕晕状态在 `SwordSystem` 权威结算 ×1.3 伤害;弓同款(客人 `arrowHit` 上行后按晕晕状态 ×1.3),套索不受醉酒影响。

### 已制作配方记录同步(2026-09)

- `PlayerSession.craftedIds` 记录每名玩家制作过的配方 id:制作在房主权威端 `CraftingSystem` 完成时写入,随 `SessionSave.crafted` 存档(可选字段,旧档缺省为空,版本不变)。
- 客人端经 HUD 快照新增字段 `craftedIds` 回流,供工作台列表(未制作配方置灰展示)与合成图鉴「已制作」标签使用;离散集合,快照增量整组下发。

### 烹饪台同步(2026-09)

- 新增世界段 `cookingStations`(落点 + `fuel/boilKind/boilQueue/tickLeft/outKind/outCount`)与动作 `useCookingStation/cookingAddFuel/cookingRoast/cookingBoil/cookingCollect/cookingTakeBoil`:放置/添柴/烤制/煮汤/收取由客人上行、房主权威结算,台上状态经世界增量回流。
- 煮制计时(每 5 秒 1 份)与燃料消耗只在房主端结算产出,客人端本地倒数 `tickLeft`、本地递减 `fuel` 仅做表现,快照增量柔和对账(同冶炼炉约定);烤制(玩家站定逐份烤)与火堆烹饪同款,由各端 `updateActor` 表现、房主侧结算入包。

### 定向提示同步(2026-09)

- `Game.notify(text, actor)` 增加目标会话参数:房主代客人权威结算产生的临时提示(放置失败、箱/桶/炉/机装不下、背包满、睡觉提示、复活提示、GM 鳄鱼提示等)不再播在房主屏幕,而是通过定向事件 `{ kind: 'notice', target, text }` 广播,客人在 `netApplyEvent` 中按本人 id 过滤后走本地 notice 展示(同 `bottle` 事件的定向模式)。
- 存档版本不变;提示不进快照,断线重连期间的提示自然丢弃。

### 联机死亡掉落(2026-09)

- 联机死亡重生不再「随身全清」:房主在死亡瞬间(死亡状态沿、复活石免死不触发)执行 `dropDeathLoot`,在死亡位置生成地面掉落物(走 `drops` 世界增量,客人端可见、任何人可捡回);重生倒计时结束后只做清零与传送。
- 掉落规则:背包中的丛类植株(`berryBush`/`shrubBush`/`grassTuft`)必定全部掉落;其余背包装备按每格数量 60%(`DEATH_DROP_RATIO`,四舍五入)掉落;箭/鱼饵(独立弹药存储 `PlayerSession.ammo`,不占背包格)同样按数量 60% 掉落并扣除;四个穿戴栏位与每件已拥有工具各有 60% 概率掉落,未掉落部分随重生清零直接丢失。
- 工具掉落物携带可选 `tier` 字段(存档 `drops` 与世界增量同步,旧档缺省视为无等级):捡回工具类掉落物时不进背包,而是把该工具重新点亮到掉落时的等级(`pickupDrop` 内特殊处理);等级只升不降。「捡回」卡片按等级显示工具名(如「石斧」「铁斧」)。箭/鱼饵掉落物捡回进弹药存储。
- 弹药同步:客人本地放箭/抛竿即时扣自己的弹药(与背包本地先扣一致),房主在 `arrowShot` 动作中权威补扣;弹药数量经 HUD 快照 `arrow`/`bait` 字段回流对齐(`netApplyHud` 直接覆盖,数量增加时补拾取飘字)。
- 复活石免死不触发掉落(不走重生流程)。

### 客人 HUD 闲置淡出(2026-09)

- 修复客人端 UI 永不淡出的问题:此前房主 `hudFor` 给客人的 HUD 快照 `busy` 恒为 false。现改为房主在权威会话循环中为每个会话累计 `PlayerSession.hudIdleTime`(移动/作业/睡觉/钓鱼中清零,判定与本地 `pushHud` 同源 `isSessionActive`),`hudFor` 据此为每个客人各算 `busy`,闲置满 5 秒后客人端 HUD 同样淡出。

## 玩家程序动作表现

本地玩家、房主远程会话与客人显示的其他玩家共用 `PlayerAnimator`，腰部、肩肘及髋膝在各端本地求姿态。交互仍经 `NetGuest.action` 上行、房主 `Actions.ts` 和对应系统权威结算；动作类型沿用 `PlayerState.action` 快照回流，同类型快照不会重置动作时间。连续作业从本端首次观察到该动作起计时，允许网络延迟造成的相位差，不保证工具落点与权威产出逐帧一致。命中、采集粒子等仍使用既有事件补播；本次不增加动画事件或协议字段。

走路相位按本端实际水平位移推进，远程角色使用快照插值后的位移；动作切换通过指数插值柔和过渡。视觉腰部转动与重心偏移仅作用于模型节点，不写入网络位置、碰撞或存档。挥剑保留移动中播放，其他作业仍在站定时显示。睡眠、死亡释放作业关节残留，重生重置表现。协议版本和存档版本不变。详见 `player-animation.md`。

双手采集握点由各端 `ArmReach` 根据同一模型和工具安装变换本地求解，砍树/挖矿沿用既有 action 与 tool 快照，无新增关节坐标或抓握事件。砍树/挖矿的右侧转肩挥落，以及空手采集的双手身前交替拨拢只作本地视觉表现，不额外触发资源结算或粒子事件。

进食嘴部目标和钓鱼双手竿尾握点在各端由同一 `PlayerAnimator` 求解，沿用 eat/cast/fish 动作类型及工具快照。挥剑闪光由各端观察到 slash 后采样实际剑身变换生成，不重复发送命中或伤害事件；权威伤害仍走既有 swordHit。游泳按各端水位和头部中心校正高度，水平移动/游泳判定规则不变，位置快照继续回流。无新增协议字段及存档字段，不调整版本。

所有玩家模型统一使用角色自身右手（局部 -X）主握工具及安放物，客人和房主共用修正后的左右关节及辅助握点定义。既有工具/动作快照直接驱动外观，无新增手别字段、事件或存档版本变更。

## GM 本机性能诊断
性能开关、帧耗时和 renderer.info 统计仅保留在各端 Game 实例，不上传动作、不进入房主权威状态、不下发快照或事件，不写入存档。房主与客人独立开启，报告标记单机/房主/客人；客人报告反映客人设备的本地表现，不能代表房主负载。诊断不改变模拟与结算。

## 静态部件绘制合并
围栏、土壤、浆果与树木的静态部件合并仅改变两端模型构造；各端从原有权威状态创建合并模型，生长/采集/连接变化仍由原快照和事件驱动。无新增网络字段，不修改存档版本；客人移除土壤同时释放本地渲染资源。详见 [绘制优化](render-batching.md)。

## 设施与作物静态绘制
作物、箱体、工作台、纺织机、桶体、净化器、神龛、兔子洞、帐篷、围栏门与火堆/烹饪台静态部件在各端本地构造时合并。动态部件仍由原运行时表现驱动；不新增动作、快照字段或事件。作物换阶段和快照删除时释放本机旧模型，存档版本及持久化 ID 保持不变。详见 [绘制优化](render-batching.md)。

## 大消息分片传输
`PeerNet` 控制通道在序列化后超过约 60KB 的消息(如长进度存档的 `welcome` 全量状态)会按 UTF-16 单元切成多帧 `__frag` 消息,经可靠有序通道依次发送,接收端按分片 id 重组后再走原有分发路径。分片对上层协议完全透明,消息结构、协议版本与存档版本均不变。此前单条 DataChannel 消息超过浏览器安全上限(约 256KB)会导致大档玩家加入时 welcome 发送失败、卡在连接阶段。

2026-09-11(迭代):删除 `useFacility` 动作(`NET_PROTOCOL_VERSION` 24→25)——背包「使用」可放置道具改为切入手持安放模式,经既有 `tool` 动作(携带 placeKind)上行,放置结算统一由 `AutoPlaceSystem` 站定放置路径触发(`settleFacility` 仅保留 cell 入参);制作完成自动手持收窄为火把/火堆/一级工作台,其余设施产物入包,不影响协议。存档不变。

## 男孩整套造型同步

- 全房间 GM 视觉配置 `boyModelVariant` 允许 original / child / teen。客人经 `NetGuest.action('gmConfig', ...)` 上行，房主 `Actions.ts` 校验配置后可靠广播 GM 事件，无新增玩法结算。
- 房主 `PlayerSnapshotBuilder` 在 `PlayerState` 携带可选 `boyModelVariant`，客人从完整还原的玩家列表中校验并应用。新加入、重连和事件漏收由后续快照恢复，旧载荷缺省 original，无需单独动作补播。
- 各端 `Player.update` 将配置交给统一预览控制器，仅在版本或性别变化时切换独立模型并释放旧资源。女孩恢复原始材质。动作姿态、工具和伤口沿用原有同步，各方案嘴部位置供吃东西动作读取。
- 各端同步隐藏预览男孩的穿戴装备网格，保持权威装备数据、属性和存档不变；切回原版或女孩恢复装备外观。方案选择不持久化，不修改存档版本。

- 原版男孩的肩肘、膝踝步态和椭圆头型由各端按既有性别、GM 造型及实际移动速度生成。房主与客人共用实现，不增加网络字段；动画不改变权威位移、碰撞或命中，步态相位允许各端不同。女孩维持原表现，存档版本不变。

- 原版男孩的露颈肩线和平头由各端模型工厂生成，沿用性别与 GM 造型同步，不新增网络或存档字段；头部高度变化仅影响本地模型表现和既有头部挂点。
