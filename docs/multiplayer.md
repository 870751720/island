# 多人联机(WebRTC 房主权威)

## 背景

游戏目前是纯单机:一个 `Game` 实例绑定唯一 `Player`,玩法判定、存档、HUD 全部围绕单玩家。目标是支持多人联机共玩同一座岛(人数不设上限),且不引入任何游戏服务器、保持 GitHub Pages 纯静态部署。

## 需求描述

- 多人(2 人即可开玩,人数不设上限)在同一个房主权威世界中共同生存；岛形由地形种子生成，自然资源由房主持有并同步完整状态。
- 传输:WebRTC DataChannel 玩家直连(房主星形拓扑),第三方服务不承载游戏数据。
- 信令:五位数字房间码或二维码,通过国内公共 MQTT 自动交换 WebRTC 握手信息。
- 权威模型:房主客户端跑完整玩法模拟;客人只跑表现层 + 自身移动预测。
- 存档:联机时房主持档;单机模式保持现状;存档结构变化时 SAVE_VERSION +1。
- 断线:房主退出即全房解散;客人断线由房主按超时移除该会话。

## 设计方案

### 连接状态与网络限制

- 房间信令回复只代表找到房间，客人此时显示“正在连接房主”；只有两条 WebRTC 数据通道都打开后，才显示“等待房主开始游戏”。
- 房主和客人的握手连接均在 30 秒内未完成时回收。客人显示当前网络暂时无法连接、确认房主在线或切换网络的提示，并允许重新加入；失败和重试清理旧连接，迟到回调不影响新连接。
- 连接失败无法确定具体运营商或 NAT 类型，不将运营商故障作为确定诊断。当前仅提供 STUN 直连，受限网络仍可能无法加入；本提示不等于修复网络穿透。
- 后续可接入国内托管 TURN，或将游戏消息改由托管 WebSocket/MQTT 中继转发，无需玩家自行维护服务器。公共 MQTT 服务面向测试，不能默认当作稳定游戏中继；正式接入需确认国内节点、额度、消息频率、认证和延迟。房主仍负责权威结算，客人动作上行与快照、事件回流语义保持一致。
- 本次不改变网络消息格式与存档版本。

### 模块划分

- `src/game/net/`:消息协议(`Protocol`)、WebRTC 连接(`PeerNet`)、在线房间信令(`Signaling`)、房主与客人会话总管。
- `src/game/mp/`:每玩家会话(`PlayerSession`:player + survival + inventory + equipment + tools)、远程玩家驱动(`RemoteDriver`)、世界状态同步(`WorldSync`)。

### 资源模型生命周期与白屏排查

- 房主仍权威结算资源采集、生长、放置与移除，客人沿用世界增量和完整快照回流；不新增网络字段、不改变存档版本。
- 客人处理资源列表时保留未变化树木的网格。只有树种、生长外观或树桩外观发生变化时才替换网格，单纯的可见性、朝向和计时变化不重建模型。
- 替换树模型、移除资源和退出游戏时释放资源点独占的几何体与材质；同一资源内部共享的网格资源只释放一次，避免持续游玩时 GPU 资源累积。
- WebGL 上下文丢失时允许浏览器恢复，并在控制台记录客人模式、几何体/纹理数量、绘制调用与画布尺寸；恢复时重新同步画布尺寸并记录恢复事件。浏览器不保证一定恢复，不能将输入仍可上行视为本地渲染正常的证据。
- 资源同步重复建模且不释放旧网格是已确认的泄漏；具体设备的白屏仍需结合上下文事件或异常堆栈判断，不将所有白屏一概归因于内存压力。

### 权威与同步

- 房主侧为每名客人建一个 `PlayerSession`(复用本地 Player 物理与动画,输入由网络摇杆写入 `player.input.setJoystick`,保证与本地移动完全一致的判定)。
- 客人侧:收到地形种子后重建相同岛形，再按房主完整资源列表建立资源布局；远程玩家用 Player 的「遥控模式」(`setNetPose` 插值)表现；权威状态(资源点/掉落物/放置物/动物/昼夜/天气)由 `WorldSync` 增量应用。
- 消息:客人→房主 `input`(摇杆)与 `action`(按钮语义,即 Game 公共方法参数化);房主→客人 `welcome`(种子+初始状态)、`snapshot`(10–15Hz)、`event`(音效/特效/拾取/死亡)。

### 里程碑

- M1 多玩家抽象:Player 遥控模式、PlayerSession、Game 会话化、动物按最近玩家结算(单机行为不变)。
- M2 状态收拢与实体 id:按会话结算的交互系统(采集/制作/火堆/木箱/钓鱼等)、掉落物与动物 id、SAVE_VERSION=26、权威随机收敛。
- M3 网络层:PeerNet/RoomCode/NetSession、房主权威模拟、客人 guest 模式。
- M4 联机 UI:房间创建/加入、lobby、断线处理。
- M5 打磨:名字标签、事件同步、死亡规则联机化。
# 地图表现

地图不新增网络协议。房主直接读取权威玩家会话和设施系统；客人读取已有玩家姿态快照与工作台、床、火堆世界增量在本机重建的状态。地图只做只读表现，不参与结算。

## 海水视觉

房主与客人使用相同地形种子在本机生成海水深度纹理，按各自镜头覆盖海面；波纹、浅滩光纹与沿岸白沫由本地时间驱动，相位可不同。这些效果只参与渲染，不改变水位或游泳判定，不新增动作上行、快照字段或事件补播。移动与生存消耗继续由房主权威结算，存档版本保持不变。

### 动物与螃蟹补充节奏(2026-09)

动物(兔/羊/鹿/狼/熊)、螃蟹、鸟的种群补充改为逐只冷却(120~900 秒按物种),仍只在房主端结算,新个体沿用既有姿态快照回流、客人按 id 补建,不新增协议字段。

## 迭代记录

### 已制作配方记录同步(2026-09)

- `PlayerSession.craftedIds` 记录每名玩家制作过的配方 id:制作在房主权威端 `CraftingSystem` 完成时写入,随 `SessionSave.crafted` 存档(可选字段,旧档缺省为空,版本不变)。
- 客人端经 HUD 快照新增字段 `craftedIds` 回流,供工作台列表(未制作配方置灰展示)与合成图鉴「已制作」标签使用;离散集合,快照增量整组下发。

### 烹饪台同步(2026-09)

- 新增世界段 `cookingStations`(落点 + `fuel/boilKind/boilQueue/tickLeft/outKind/outCount`)与动作 `useCookingStation/cookingAddFuel/cookingRoast/cookingBoil/cookingCollect`:放置/添柴/烤制/煮汤/收取由客人上行、房主权威结算,台上状态经世界增量回流。
- 煮制计时(每 5 秒 1 份)与燃料消耗只在房主端结算产出,客人端本地倒数 `tickLeft`、本地递减 `fuel` 仅做表现,快照增量柔和对账(同冶炼炉约定);烤制(玩家站定逐份烤)与火堆烹饪同款,由各端 `updateActor` 表现、房主侧结算入包。
- 火堆挖掘回收:挖掉熄灭火堆在房主侧结算掉落「熄灭的火堆」道具,入包经 HUD 快照回流。

### 冶炼炉同步(2026-09)

- 新增世界段 `smelters` 与动作 `useSmelter/smelterFeed/smelterCollect`:放置/投料/收取由客人上行、房主权威结算,炉内 `ore/ingot/tickLeft` 经世界增量回流;冶炼计时只在房主端推进(同饵料桶)。
- 纺织机同款约定:世界段 `looms` 与动作 `useLoom/loomFeed/loomCollect`,机内 `rope/cloth/tickLeft` 经世界增量回流,织布计时只在房主端推进。

### 海水净化器同步(2026-09)

- 新增世界段 `waterPurifiers`(落点增量回流)与动作 `useWaterPurifier`:放置由客人上行、房主权威结算;锄头挖走同饵料桶,各端 `updateActor` 表现、房主侧结算上报。
- 靠近净化器自动喝水无离散事件:各端本地用 `WaterSystem` 模拟(复用水洼喝水约定),口渴数值随生存快照回流。

### 定向提示同步(2026-09)

- `Game.notify(text, actor)` 增加目标会话参数:房主代客人权威结算产生的临时提示(放置失败、箱/桶/炉/机装不下、背包满、睡觉提示、复活提示、GM 鳄鱼提示等)不再播在房主屏幕,而是通过定向事件 `{ kind: 'notice', target, text }` 广播,客人在 `netApplyEvent` 中按本人 id 过滤后走本地 notice 展示(同 `bottle` 事件的定向模式)。
- 存档版本不变;提示不进快照,断线重连期间的提示自然丢弃。

### 联机死亡掉落(2026-09)

- 联机死亡重生不再「随身全清」:房主在死亡瞬间(死亡状态沿、复活石免死不触发)执行 `dropDeathLoot`,在死亡位置生成地面掉落物(走 `drops` 世界增量,客人端可见、任何人可捡回);重生倒计时结束后只做清零与传送。
- 掉落规则:背包中的丛类植株(`berryBush`/`shrubBush`/`grassTuft`)必定全部掉落;其余背包装备按每格数量 60%(`DEATH_DROP_RATIO`,四舍五入)掉落;四个穿戴栏位与每件已拥有工具各有 60% 概率掉落,未掉落部分随重生清零直接丢失。
- 工具掉落物携带可选 `tier` 字段(存档 `drops` 与世界增量同步,旧档缺省视为无等级):捡回工具类掉落物时不进背包,而是把该工具重新点亮到掉落时的等级(`pickupDrop` 内特殊处理);等级只升不降。「捡回」卡片按等级显示工具名(如「石斧」「铁斧」)。
- 复活石免死不触发掉落(不走重生流程)。

### 全局系统提示(2026-09)

- 新增全局事件 `{ kind: 'sysNotice', text }`(`NET_PROTOCOL_VERSION` 升至 18):房主经 `Game.sysNotify` 广播给所有客人并在本地展示,客人在 `netApplyEvent` 直接走本地 notice,无需过滤。
- 触发点:客人加入(`NetHost.onGuestJoined`,hello 结算时)、客人离开/掉线(`onGuestLeft`,含心跳超时)、任意玩家死亡(房主权威死亡结算沿,复活石免死不触发)。提示文案如「XX 加入了游戏 / 离开了游戏 / XX 倒下了」,所有人(含房主)屏幕可见。

### 权威状态与重连对账

- 玩家、动物、环境生物的字段增量依赖前序状态，统一走可靠有序控制通道，不能丢弃或仅保留同类型最后一包；摇杆输入带序号，继续走可淘汰实时通道。位置表现仍使用客人本地预测与插值。可靠传输在弱网下可能增加状态延迟。
- 客人从收到欢迎包到 Game 注册回调期间缓存后续消息，begin 时按顺序应用，避免加载期间丢失世界变化或初始快照。
- 所有玩家快照包含完整穿戴栏位（空栏为 null），其他玩家的模型按房主穿戴状态刷新，包括死亡清空、换装与卸装；本人背包仍由 HUD 权威回流。
- 动物首次同步与每五秒校正发送战斗动物和普通动物合并的完整集合（包括空集合），客人清除集合之外的个体；新建动物必须采用房主 id，不能使用客人自增 id。死亡动画仍由存活状态变化驱动。
- 资源再生和树木生长仅由房主结算；客人只更新风摆和受击表现，ready 等离散状态由世界增量与全量对账更新，不能根据旧倒计时自行恢复可采集状态。
- 网络协议版本为 20，双方需刷新到同一版本；存档结构与 SAVE_VERSION 不变（兔子洞 `burrows` 为可选字段，旧档缺省视为无）。

### 兔子洞同步(2026-09)

- 新增世界段 `burrows`(详见 rabbit-burrow.md):洞实体带稳定 id,增删与挖废(`set state=abandoned`)走世界增量;客人端不本地生成,由欢迎包世界状态与增量补建;废弃洞的重生倒计时仅房主推进、不入网络比较(同资源再生)。
- 挖洞无客人动作上行:客人的锄头挖掘由房主 `updateActor` 对远程会话统一结算(同海水净化器);藏在洞内的兔子被压死由房主 `Wildlife.killHidden` 权威结算,战利品走掉落物世界段回流。
- 兔子躲藏是房主 AI 状态:姿态快照 `AnimalPose` 新增 `hidden` 标记,客人端同步隐藏/显示模型并跳过躲藏个体索敌;`NET_PROTOCOL_VERSION` 19→20。

### 进食「吃饱」按钮(2026-09)

- 新增动作 `eatUntilFull`(参数同 `eatFood`):客人上行,房主以该客人会话权威结算;连续进食(吃完一份饥饿未满且还有存货则自动吃下一份)在 `EatingSystem.startFull` 内推进,客人端经 `eatName/eatProgress` 快照表现,无需新增字段或事件。

### 套索与拴羊(2026-09)

- 新道具「套索」(绳线×3,工作台):持有即进入工具轮;移动瞄准、停手掷出,交互完全复用弓的「本地判定+上行结算」例外约定。
- 三个动作:`lassoThrow [dx, dz]`(掷出瞬间房主补甩索动作窗口、广播 `lassoThrown` 视觉事件,不扣道具,仿 `arrowShot`)、`lassoHit [animalId, x, z]`(客人本地扫掠判定套中后上行,房主扣除该客人一个套索并 `Wildlife.lassoSheep` 权威置拴绳状态,仿 `arrowHit`;掷空不扣道具、绳圈收回,无上行动作)、`lassoStake / lassoUntie`(脚下打桩 / 解开身旁被拴的羊,套索回收经 HUD 快照回流)。
- 拴绳状态同步:姿态快照 `AnimalPose` 新增可选 `leash: { by: 会话id } | { stake: {x, z} }`,客人端镜像 `netLeash` 用于绳子渲染(玩家↔羊、桩↔羊两端本地推导,不做网络对象);被拴/被牵的羊临时按 25Hz 战斗频率下发;`NET_PROTOCOL_VERSION` 21→22。
- 拴羊桩为新增世界段 `stakes`(落点 + 稳定 id),打桩/拆桩走世界增量;拴羊 AI(牵引跟随/绕桩吃草)只在房主端结算,客人端只插值姿态。
- 断线兜底:客人离场时其牵着的羊由房主释放、套索掉在羊脚下;被拴在桩上的羊不受影响。存档为纯快照:被牵着(未打桩)的羊不入档,存档数据里给玩家多记一个套索,现场状态不动(联机欢迎包同);拴住的羊随 `stakes` 入档,读档在权威端于桩位重新生成。牵着羊时工具锁死为套索(`tool` 动作被房主忽略),客人端经 `Wildlife.leashedBy` 的快照镜像(`netLeash.by`)同样能判定自己正牵着羊,交互屏蔽与工具按钮表现两端一致。

#### 迭代 2026-09-07:联机套索表现修复

- 新增可靠事件 `lassoCaught { actor }`:套索命中权威结算成功(房主本地命中或结算客人上行 `lassoHit`)时,房主收掉该会话的视觉绳并广播;各端收到后立即移除该玩家的掷绳表现,不再播完"伸出→收回"被误读为没套中。牵引绳由既有拴绳渲染接管。
- 修复客人端"羊消失一段时间":羊被牵走时从 passive 快照列表转入 combat 列表,过渡帧内 passive 差分发 `remove`、combat 发 `set`,合并成一条消息后客人端 `applyEntityDelta` 先 set 后 remove 把羊误删(直到下一次 combat 位置变化超过量化精度才恢复)。`NetHost` 合并动物增量时过滤掉同帧已出现在 `set` 里的 `remove`(反向移回 passive 同理),不新增协议字段。

### 分级帐篷表现

床的 1～3 级场景模型和掉落物使用共享的程序化帐篷模型。房主与客人均由既有 `beds` 数据的等级和朝向构建外观；放置、拆除、睡觉仍由房主权威结算，客人沿用动作上行、世界增量和玩家姿态快照，不增加网络字段。持久化 ID 和存档版本保持不变。
