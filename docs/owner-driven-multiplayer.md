# 玩家本机驱动与共享世界结算

## 背景

服务器中转往返约 400ms 时，房主重放客人摇杆再回传位置会造成停步后滑动；房主推进采集、进食等个人计时，也会让动作和提示落后于手指操作。

## 需求描述

- 每位玩家独立处理自己的移动、碰撞、动作、目标选择和操作进度，移动与取消即时生效。
- 房主接收客人姿态，动物 AI、伙伴、环境演化与共享世界仍只由房主运行。
- 保留统一的库存、生存、任务和共享实体结算，防止重复发奖、争抢复制和错误操作邻近设施。
- 手机触控入口不变；直连和服务器中转使用同一套玩法协议。

## 设计方案

### 同步职责

| 内容 | 操作者本机 | 房主 |
| --- | --- | --- |
| 玩家移动与碰撞 | 直接运行，不等待回流 | 接收姿态，显示模型平滑，不重跑客人摇杆 |
| 采集、吃喝、制作、挖掘、播种、亲自烹饪 | 选择目标、播放声音动作、推进计时、提交完成请求 | 复核工具、距离、材料与目标状态，结算产物和共享变化 |
| 钓鱼 | 立即抛竿，本机处理咬钩窗口与宝箱转盘 | 消耗鱼饵、抽取鱼获和等待方案，按抛竿凭据发奖一次 |
| 睡觉、研究 | 即时启动个人表现 | 确认条件并推进世界时间或研究结果 |
| 动物、伙伴、共享设备、天气、生长 | 插值及视觉表现 | AI、随机、生存伤害、设备生产与世界演化 |
| 背包与奖励 | 显示确认后的库存 | 统一消费、恢复和发奖 |

### 消息与隔离

`ownerPose` 以 20Hz 携带姿态序号、`epoch`、坐标、朝向、移动及动作状态。房主采用新序号的位置，其他玩家继续按快照插值。本人忽略普通回流的位置、动作和工具；复活增加 `epoch`，强制恢复位置并清理旧计时与待确认操作。不同代次的完成请求和回调不能影响新角色。

可靠 `action` 携带独立动作序号、操作发生时的姿态以及稳定目标。房主去重后结算：如果更新的无序姿态已经先到，临时使用动作时的位置校验，然后恢复新位置，避免合法采集因后续移动被错误拒绝。库存变化立即下发，再发送 `actionResult`，无需再等常规 HUD 周期。

`collectHit` 携带资源阶段，防止旧砍树命中作用于新树桩。设施操作绑定实体 ID，原目标被别人删除后拒绝，不自动操作相邻对象。土壤回收区分作物与土壤阶段，工作台升级绑定原等级。待确认安放格不重复提交。

### 个人操作与公共结果

个人进度、本人的高亮、音效和动作不由迟到 HUD 驱动。每份完成才发送 `eatPortion`、`drinkRound`、`craftFinish`、`workFinish` 或 `place`；客人不提前发奖、删除世界实体或修改生存值。资源争抢时以房主收到请求后的实际可用状态为准。

客人亲自烤制、火堆烹饪按完成份数扣料，不预扣整批，取消未完成部分无需退款；单机仍保留原有批量预留和退款行为。独立运行的煮制、酿酒、加工等公共设备继续由房主推进。

钓鱼方案只由房主抽取。本机收到方案后启动等待与反应计时，取消带本次抛竿编号；迟到方案不能重启旧抛竿，完成凭据只能消费一次。即使较新的移动姿态先到，合法的旧成功请求仍能按凭据结算。

### 边界与兼容

本方案信任玩家本机的移动与个人计时，不提供服务器权威防作弊。它消除本人被普通旧快照拉回的路径，不能消除看到队友、动物伤害和共享库存确认的网络延迟，也不能替代手机帧率优化。

协议版本为 51，房主和客人必须使用相同构建；持久化结构及 ID 保持不变，`SAVE_VERSION` 不变。游戏图鉴的联机分工说明同步补充即时操作、延后确认和资源争抢行为。

## 验证

- `scripts/test-owner-network.mts`：模拟单程 200ms，验证真实 NetHost/NetGuest 请求和确认、重复与乱序、旧复活代次、同代次本人快照不回拉、资源争抢、稳定设施目标、本地采集/吃喝/回收计时和钓鱼反应/重复发奖。
- 设施、料理研究和联机连接回归脚本覆盖原有结算及连接生命周期；类型检查和 H5 构建检查静态集成。
- 用户使用同版本双端进入服务器中转，验证快速停走与反向、采集后移动取消、双方争抢、连续播种、吃喝/制作/回收、钓鱼及死亡复活；实际手机手感与图形表现由用户运行验证。
