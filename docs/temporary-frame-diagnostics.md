# GM 卡顿采集

## 背景

真机反馈逻辑 CPU 可能达到 500 ms。原性能面板仅提供平均值，无法定位耗时系统；静止存档的部分逻辑模拟未复现，需要采集实际操作中的主线程尖峰。

## 需求描述

GM → 世界 → 本机性能诊断下方提供“卡顿采集”卡片。默认关闭，点击开始后可关闭 GM 继续游玩，卡顿后返回结束采集；最多两分钟自动停止，不弹窗打断游戏。关闭面板或切换页签不会取消采集，返回后可查看和复制报告。报告仅在当前 Game 实例内保留，重新采集替换旧报告。剪贴板不可用时点击文本框全选后长按复制。卡片、按钮和内嵌报告沿用游戏奶油绿主题，按钮至少 44px，适配手机小屏。

## 设计方案

- 独立 FrameDiagnostics 模块，关闭时仅保留快速开关判断，不读取分段时钟、不积累报告；开启时按游戏循环中的阶段记录墙钟耗时，有少量诊断开销。GM 卡片仅在面板挂载且采集中每秒检查状态，退出面板即清除 UI 定时器。
- 区分玩家导航、天气、音频、动物 AI（含觅食寻路）、伙伴、植被、粒子、个人工具、设施交互、设施生产、提示、头顶 UI、任务、渲染准备、WebGL 提交、死亡、自动存档、HUD 与自动装备。
- 动物内部进一步区分补刷准备、追击准备、移动战斗与动画、觅食移动与驯养、觅食搜索队列和繁殖，阶段互不重叠。
- 保存各阶段均值/峰值、最慢十个 CPU 帧及其阶段明细、最长五个帧间隔及前一帧 CPU、首末绘制和资源计数。历史容量固定，不积累逐帧日志。
- 超过一秒的前台样本仍然保留；后台样本不计入汇总，恢复页面后的长帧间隔可能包含后台时间。
- 所有阶段均为主线程墙钟时间，可能包含 GC 或浏览器等待，不是纯算法时间。WebGL 提交不是 GPU 计时。React 在游戏循环外的工作可能只表现为较长帧间隔，不能直接归为动物寻路。
- 只记录设备 UA、视口、角色、游戏天数、工具/移动状态和性能数据，不读取存档码、玩家名字或完整存档。仅本页内存保存，由玩家手动复制，不自动上传、不写游戏存档。
- 单机/房主记录权威模拟；客人记录本机插值和交互。诊断不经 NetGuest.action 上行，不改变快照或玩法。图鉴及存档版本无需变化。
- 原 GM 性能面板和卡顿采集独立开关，共用帧回调；采集结束后按原 GM 开关恢复回调。

## 验证

`node scripts/test-frame-diagnostics.mts` 验证 500 ms 尖峰归属、前台超秒间隔保留、历史容量、首末资源计数、后台过滤、两分钟停止和重新开始清空。类型检查和 H5 打包后由用户完成手机按钮、复制以及实际卡顿采集验证。
