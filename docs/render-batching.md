# 重复摆放物体绘制优化
## 背景
大量围栏、土壤、浆果丛和树木的程序模型由独立小网格拼装，物体增多后绘制次数明显上升。
## 需求描述
减少静态部件的绘制次数，保留手机端外观、阴影、积雪、采集与生长表现，兼容旧存档和联机。
## 设计方案
- `core/mergeClayMeshes.ts` 在模型创建或外观重建时合并物体内部的静态黏土网格，将局部变换烘焙进几何体，将线性颜色烘焙进顶点色；合并不使用多材质 groups。
- 按落叶枯黄 shader、投影和接收阴影分别分组，保留原有季节与阴影行为。原独占资源、合并临时几何体及时释放。输入不能包含需独立动画或显隐的部件，带贴图、透明及非季节 shader 的模型跳过。
- 普通直线木围栏 5→1 网格，四向木围栏 9→1；连接变化仍按原流程重建，围栏门保持独立运动。
- 土壤 8→2 网格，按接收阴影属性分组，保留按格子确定的土坷垃散布；铲除、清空及客人删除土壤时释放资源。
- 成熟浆果丛 5→2 网格：四颗浆果合为一组，与叶丛分开，采集和再生继续只切换浆果显隐。
- 成熟挂果果树 17→2 网格；树木按积雪/枯黄与投影属性合并，生长、摘果、砍伐时重建，根节点仍执行受击与风摇动画。
- 以上为单物体模型网格数，实际绘制次数还受到可见性、阴影等影响，不承诺固定 FPS。保留逐物体视锥剔除，不跨整个岛合并；几何面数基本不变，非索引顶点会增加部分几何体数据，换取较少绘制提交。
- 性能验收：用户在同存档、地点、视角、天气下比较 GM 性能报告的 FPS、绘制次数及渲染提交 CPU；开发检查使用类型检查与生产构建。
- 主客端共用模型工厂。房主结算、客人动作上行及状态快照不变，无新增状态字段或事件，SAVE_VERSION 不变。
