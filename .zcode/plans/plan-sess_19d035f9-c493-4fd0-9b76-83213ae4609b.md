# 四人联机改造方案(WebRTC 房主权威 + 手动房间码)

## 总体架构

- **传输**:WebRTC DataChannel,房主星形拓扑(房主↔3 客人共 3 条直连),无任何第三方服务器,静态部署 GitHub Pages 不变。STUN 用 Google 免费 `stun:stun.l.google.com:19302`。
- **信令(手动房间码)**:房主在房间界面为每个朋友生成一个加入码(SDP offer 压缩+Base64),朋友粘贴后生成回传码(SDP answer),房主粘贴回传码即完成该玩家的握手。三次微信发码即可集齐 4 人。
- **权威模型**:房主客户端跑完整玩法模拟(现有 Game 逻辑);客人客户端只跑表现层(渲染、动画、粒子、音效、相机、小地图迷雾),玩法判定全部由房主结算。客人本地对自己的移动做预测+校正,对其他玩家做插值。
- **存档**:联机时房主持档(沿用现有 SaveSystem,仅保存房主视角的全部玩家会话);单机模式保持现状。SAVE_VERSION +1。

## 新增模块(代码结构)

```
src/game/net/
  Protocol.ts      消息类型定义(TypeScript 判别联合)
  PeerNet.ts       WebRTC 连接管理(房主侧多连接/客人侧单连接、断线检测)
  RoomCode.ts      房间码编解码(SDP 压缩 + Base64,含序号)
  NetSession.ts    联机会话总管:输入上行、快照下行、事件分发
src/game/mp/
  PlayerSession.ts 每玩家会话:player + survival + inventory + equipment + tools
  RemoteDriver.ts  远程驱动器:把网络 pos/rot/action 写入 Player(插值/预测校正)
  WorldSync.ts     世界状态快照/增量收集与应用(props/drops/放置物/动物/时间/天气)
```

消息协议(概要):
- 客人→房主:`input`(20Hz,seq+摇杆+当前动作键)、`action`(按钮语义,如 craft/eat/place/pickup,即现有 Game 公共方法的参数化)、`hello`(名字)。
- 房主→客人:`snapshot`(10–15Hz:4 玩家 pos/rot/action/生存值/背包、脏集合的增量——drops、放置物、PropSave、动物位置与存活、dayTime、weather)、`event`(即时的音效/特效/拾取提示/死亡)、`welcome`(terrainSeed/propsSeed/房间初始状态)。

## 改造步骤(按里程碑分批提交,每批通过类型检查+构建+部署)

### M1 多玩家抽象(单机行为完全不变)
- `Player` 增加"遥控模式":跳过本地输入积分,位置/朝向/动作由外部写入,复用现有程序动画;`MoveInput` 仅本地玩家实例挂 window 监听。
- 新建 `PlayerSession`(player+survival+inventory+equipment+tools);`Game` 持有 `sessions: PlayerSession[]`(单机时长度 1),HUD/相机只绑 `localSession`。
- 涉及"以唯一玩家为中心"的系统按发起者会话结算:CollectSystem、CampfireSystem、CrateSystem、FishingSystem、EatingSystem、CraftingSystem、BowSystem 的 near/isBusy 判定改为传入 actor 的位置;动物/熊攻击目标从"唯一玩家"改为"最近存活玩家"。
- 掉落物、动物、放置物补短 id(同步用)。

### M2 状态收拢与存档升级
- 把需要同步的权威状态(现有各系统的 snapshot/restore 已具备大半)整合为可增量上报的结构;`WorldSync` 负责脏标记与增量提取。
- SaveSystem:SAVE_VERSION=26,存档扩展为多玩家会话结构,联机时房主保存全部会话。遵守"不写旧档兼容代码"约定。
- 房主侧把影响玩法结果的 `Math.random()`(掉落、再生、天气、陨石)收敛为权威结果,随消息广播。

### M3 网络层与权威模拟
- `PeerNet` + `RoomCode`:DataChannel 建立、心跳、断线通知。
- 房主:`NetSession` 合并本地+远程输入喂给 Game;按频率广播快照与事件;收到客人 `action` 时以该客人会话为 actor 调用对应 Game 方法。
- 客人:`Game` 支持 guest 模式——收到 `welcome` 后按种子生成相同地图;不跑权威系统,由 `WorldSync.apply` 更新世界;`RemoteDriver` 处理自身预测校正与他人插值。

### M4 联机 UI 与房间流程
- `GameCanvas` 状态机扩为 start/lobby/playing;`StartScreen` 增加"创建房间/加入房间"。
- 房主 lobby:展示逐个朋友的加入码、粘贴回传码的输入框、已接入玩家列表、"开始游戏"按钮(2 人即可开玩)。
- 客人 lobby:粘贴加入码→生成回传码→显示"等待房主开始"。
- 加入/断线的提示 HUD;断线时客人回到开始界面,房主侧该会话的玩家定格并按超时移除。

### M5 打磨
- 远程玩家名字标签、动作/工具切换的即时事件、拾取提示;死亡规则联机化(单玩家死亡不清全档,死亡玩家观战或等待队伍结束,具体先做"死亡玩家观战,房主不因单人死亡清档");夜晚/天气各端表现一致(由 time+weather type 驱动,表现层本地渲染)。
